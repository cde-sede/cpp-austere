Layer 6: objects backed by the operating system, and the services a program uses through them.

| Folder | Contents |
|---|---|
| `fs/` | `fs::descriptor`: an owned file descriptor with typed, compile-time-checked flags |
| `io/` | buffered `io::writer`, `io::reader`, `io::stream` over descriptors; `io::out()`, `io::err()`, `io::in()` |
| `print/` | `ca::print`, `ca::printf`, `ca::flush`, `ca::print_trace` |

This is where everything comes together: a descriptor from `fs/` is read through a buffered reader from `io/`, lines come out with `read_line` (layer 5), values are formatted by the engine of layer 5 straight into stdout's buffer, and errors print with their traces.

```c++
#include "ca/descriptor.hpp"
#include "ca/file.hpp"
#include "ca/flush.hpp"
#include "ca/fs.hpp"
#include "ca/print.hpp"
#include "ca/reader.hpp"
#include "ca/read_line.hpp"
#include "ca/str.hpp"

auto main(void) -> int {
	auto file = ca::fs::descriptor::open("notes.txt", ca::fs::writable | ca::fs::create | ca::fs::truncate, 0644U);
	if (!file || !file->write_all(ca::sv::str{"alpha\nbeta\ngamma\n"}) || !file->cleanup())
		return 1;

	auto input = ca::fs::descriptor::open("notes.txt", ca::fs::readable);
	if (!input)
		return 2;
	char buffer[64];
	ca::io::reader reader{*input, buffer};
	ca::str line{};
	int count = 0;
	for (;;) {
		auto got = ca::io::read_line(reader, line);
		if (!got)
			return 3;
		if (!*got)
			break;
		if (!ca::print("{:>2}: {}\n", ++count, line))
			return 4;
	}
	if (!ca::flush() || count != 3)
		return 5;
	return line.cleanup() && input->cleanup() && ca::sys::unlink("notes.txt") ? 0 : 6;
}
```

Standard output is per thread and buffered (line-buffered on a terminal), so `ca::print` takes no lock and each message reaches fd 1 whole. `ca::flush()` is its explicit cleanup: it writes out what is pending and reports the first error since the last flush, which a program should check before it exits.

## `dl/`

A dynamic loader of ca's own, in `ca::dl`: it loads ELF64 x86-64 shared objects without `ld.so` or libc, so freestanding programs (linked with libca_runtime, `-static` or `-static-pie`) can load plugins too. It is built on `ca::elf` (layer 3) and does what `dlopen` does with `RTLD_NOW | RTLD_LOCAL`:

- maps the load segments of the file into one reservation, aligned as they ask, each with the protection it asks for, the zero-filled tail of a segment included;
- loads what it needs (DT_NEEDED), breadth first: a name with a slash is a path, any other is first matched against the DT_SONAME of what is loaded, then searched for in the requester's DT_RPATH (when it has no DT_RUNPATH), LD_LIBRARY_PATH (not in a setuid program, nor when AT_SECURE cannot be read), DT_RUNPATH, and `/lib/x86_64-linux-gnu`, `/usr/lib/x86_64-linux-gnu`, `/lib64`, `/usr/lib64`, `/lib`, `/usr/lib`; `$ORIGIN` is the requester's directory; files of another class or machine are skipped;
- applies every relocation at once: relative ones (RELA and the packed DT_RELR) first, then the ones naming symbols, then indirect relative ones (their resolvers may read what the others wrote); then makes PT_GNU_RELRO read-only;
- runs the initializers, dependencies first (DT_INIT, then DT_INIT_ARRAY, each called with 0, nullptr and the environment, as glibc calls them).

A symbol a library leaves undefined resolves, in order, to:

- the program's explicit offers (the `host` argument, `dl::host_symbol`: a name and an address), which always win;
- the library's own definition, when it is linked `-Bsymbolic` (DT_SYMBOLIC);
- what the running program exports, as ld.so puts the executable first in the global scope: the defined, non-local symbols of its dynamic symbol table (`elf::image::program()`, read once on the first load). A program exports its functions and variables when linked with `-Wl,--export-dynamic` (`-rdynamic`); without it, only what the shared libraries it was linked against reference (under libc: `environ`, copy-relocated data). A static non-PIE program exports nothing: GNU ld gives it no dynamic section, even with `--export-dynamic`;
- the loader's built-ins (`__tls_get_addr`);
- the first definition in the scope of the library loaded: itself, then what it needs, breadth first.

An undefined weak symbol is 0. Hidden symbol versions are skipped; other versions are not checked. Indirect functions (STT_GNU_IFUNC) are resolved by calling their resolver, the program's included. A thread-local variable the program exports cannot be bound: the program's own block sits next to the thread pointer and has no module id in the loader's table. A library's reference to one goes on to the library's scope, so a copy the library defines itself (an inline `thread_local`) is used; when only the program defines it, the load fails with `errc::not_supported` naming the variable.

Objects are shared: loading a file already loaded (same device and inode), or a name matching a loaded DT_SONAME, adds a reference. `library::cleanup()` drops one; the last one runs the finalizers (DT_FINI_ARRAY in reverse, then DT_FINI), releases what the object needs and unmaps it. A failed load is all or nothing: what it mapped is unmapped, what it shared is released, and no initializer has run.

Failures come as a `ca::report<>` naming what failed: `undefined symbol host_note, needed by plugins/libgreet.so`, `libz.so.1: not found`, `x.so: not an ELF64 x86-64 shared object`.

Thread-local storage works as the general and local dynamic models (what `-fPIC` code uses) expect: each object with a PT_TLS segment gets a module id (R_X86_64_DTPMOD64), its variables offsets in its block (R_X86_64_DTPOFF64), and the loader provides `__tls_get_addr` itself. A thread's block for a module is made on its first access, from the segment's image, and freed when the thread exits (a thread key, so threads libc starts are covered too); blocks of a released module are freed when their thread next reaches its id, or exits. It never touches the thread pointer, so it works the same under libc, which owns `%fs`, and in freestanding programs. `find` of a thread-local variable gives the calling thread's copy. At most `dl::impl::tls_modules` (1024) objects with thread-local storage are loaded at once.

Loaded objects are visible to `ca::trace::symbolizer`: one made while they are loaded maps their files too, so a backtrace through plugin code shows its functions, files and lines.

Not supported, each refused with `errc::not_supported` rather than loaded wrong: the initial-exec TLS model (R_X86_64_TPOFF64, DF_STATIC_TLS: it needs room next to the thread pointer reserved before threads start), TLS descriptors (`-mtls-dialect=gnu2`), relocations in read-only segments (DT_TEXTREL), copy relocations, binding to the program's thread-local variables. Lazy binding is not offered: every symbol is bound at load. `libc.so.6` uses initial-exec TLS, so objects needing libc cannot be loaded: this loader is for plugins built `-nostdlib` against what the host offers or exports, or against other such objects. One lock serializes loading and unloading, held while initializers and finalizers run: they must not load or release libraries, nor make a symbolizer.

```c++
#include "ca/dl.hpp"
#include "ca/error.hpp"
#include "ca/format.hpp"
#include "ca/report.hpp"

static auto log_line(const char* text) -> void {
	static_cast<void>(text);
}

auto main(void) -> int {
	const ca::dl::host_symbol host[] = {{"log_line", reinterpret_cast<void*>(&log_line)}};
	auto plugin = ca::dl::library::make("libca_example_plugin.so", host);
	if (plugin) {
		const auto run = plugin->find_as<int(int)>("plugin_run");
		const int result = run ? (*run)(1) : -1;
		return plugin->cleanup() && result >= 0 ? 0 : 1;
	}
	ca::report<>& why = plugin.error();
	auto text = ca::format("{}", why);
	const bool explained = text && text->view().contains("libca_example_plugin.so: not found");
	if (text)
		static_cast<void>(text->cleanup());
	return why.error() == ca::errc::no_entry && explained && why.cleanup() ? 0 : 2;
}
```

## `dl/impl/`

The loader's internals. `impl::object` is one mapped shared object: its path, a copy of its program headers, its `elf::image`, its pages, its reference count, the objects it needs and its lookup scope. `impl::load`, `impl::release` and `impl::lookup` are what `dl::library` calls.

The objects live in one registry (an array of `ca::unique<object>` on `ca::heap`, so an object never moves) behind one mutex. The running program's `elf::image` is read under that mutex on the first load and kept (the program never moves; no global constructor), and every load's session points at it for symbol resolution. A load works in phases on the objects it maps, in the order it mapped them, breadth first from the root: map, resolve DT_NEEDED, build each scope, apply the relative relocations of all, then the symbolic ones from the last mapped to the first (so a dependency's indirect functions are callable when its users bind to them), protect RELRO, and run the initializers depth first. Any failure releases the root, which unmaps every object the load made and gives back every reference it took.

`impl::tls` is the dynamic thread vector. A fixed table of `tls_modules` entries, each the image, sizes and alignment of one PT_TLS segment, and a generation that changes at every registration and release, published last; each thread has a `thread_local` array of slots indexed by module id, each a block and the generation it was made for. `tls_get_addr`, the loader's `__tls_get_addr`, compares the two and makes a fresh block on a mismatch, so a module id handed to another object never shows the old one's data. It takes no lock: the table only changes under the loader's lock, and code reaching a module's variables runs while the module is loaded. The first registration creates a thread key whose exit callback frees the thread's blocks. `walk_objects` lets the symbolizer visit what is loaded (`ca::trace::impl::loaded_objects`), set on the first load so a program that never loads anything does not link the loader through the symbolizer.

## `fs/`

`ca::fs::descriptor`: an owned POSIX file descriptor whose flags are typed options (the `ca::fs` options of layer 3), combined and checked at compile time.

```c++
#include "ca/descriptor.hpp"
#include "ca/error.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	constexpr auto rw = ca::fs::readable | ca::fs::writable | ca::fs::create | ca::fs::truncate | ca::fs::cloexec;
	auto d = ca::fs::descriptor::open("descriptor_example.tmp", rw, 0600U);
	if (!d || !d->write_all(ca::sv::str{"hello, world"}))
		return 1;

	auto at = d->seek(7);
	auto rest = d->read_all();
	if (!at || !rest || rest->size() != 5U || (*rest)[0] != 'w')
		return 2;
	char head[5];
	auto got = d->read_at(head, 0U);
	if (!got || ca::sv::str{head, *got} != ca::sv::str{"hello"})
		return 3;

	*d |= ca::fs::nonblock;
	auto on = d->test(ca::fs::nonblock | ca::fs::cloexec);
	if (!on || !*on)
		return 4;
	*d &= ~ca::fs::nonblock;

	auto status = d->stat();
	if (!status || status->size() != 12U)
		return 5;
	auto again = ca::fs::descriptor::open("descriptor_example.tmp", ca::fs::writable | ca::fs::create | ca::fs::exclusive);
	if (again || again.error() != ca::errc::exists)
		return 6;
	return rest->cleanup() && d->cleanup() && ca::sys::unlink("descriptor_example.tmp") ? 0 : 7;
}
```

### Options

`open(path, options, mode)` (`make` under its generic name, what `ca::make` calls) takes an option set: readable when no access option is given, `mode` applying with `create`. Contradictions fail to compile (`exclusive` without `create`, `truncate` on a read-only file), and an option the platform lacks (`clofork` on Linux) fails with `errc::not_supported` before anything happens.

After opening, `d |= options` turns options on, `d &= ~options` off, and `test(options)` checks them. Each option knows its domain, so only the fcntl calls the domains need are made: one F_SETFD for `cloexec`, one F_SETFL for `nonblock` and `append`. `set` and `clear` are the fallible forms, all or nothing (an earlier domain rolls back when a later one fails), and report an unsupported option as `errc::not_supported`; the operators trap on failure and refuse an unsupported option at compile time. Open-time options (`create`, `truncate`) cannot change afterwards, and `d &= options` without the `~` is deleted, since it would clear every other flag: both are compile errors.

### Ownership

A descriptor is one int and relocates with a memcpy. `cleanup()` closes it (the descriptor is gone even when close fails, and a closed one succeeds); the destructor closes silently as a failsafe; assigning over an open one traps. `adopt(fd)` takes ownership of a raw descriptor, `release()` gives it up, `native()` reads it without giving it up, and `duplicate(options)` opens a second descriptor on the same open file, sharing offset and status flags.

The I/O methods mirror `ca::sys`: `read`, `read_all`, `write`, `write_all`, `read_at`, `write_at`, `seek`, `sync`, `sync_data`, `resize`, `allocate`, `chmod`, `chown`, `stat`. For buffered I/O, wrap it in an `io::reader` or `io::writer` (borrowed) or a `buffered_reader` / `buffered_writer` (adopted).

## `io/`

Buffered I/O over file descriptors, and the process's standard streams.

| Type | Buffer | Descriptor |
|---|---|---|
| `io::writer` | borrowed: memory the caller provides | borrowed |
| `io::reader` | borrowed | borrowed |
| `io::stream` | two borrowed buffers, a reader tied to a writer | borrowed: a socket, a terminal or a pipe pair |
| `io::buffered_writer<A>` | owned, from A, resizable | borrowed (`over`) or owned (`adopt`) |
| `io::buffered_reader<A>` | owned, from A, resizable | borrowed or owned |
| `io::out()`, `io::err()`, `io::in()` | per-thread stdout, stderr, process stdin | fds 1, 2 and 0 |

### Writers

An `io::writer` is a windowed writer (`io::is_windowed_writer`): `ca::print` and `format_to` format straight into its buffer, which is written out according to its `buffering` policy: `full` when it fills or on `flush()`, `line` also after every message holding a newline, `none` after every message. Each call returns its own error, and the first error since the last check is kept, sticky, so code that writes in many places checks once with `flush()`. When writing out fails, the unwritten bytes stay pending: `flush()` retries them and `discard()` drops them; nothing is retried behind the caller's back.

```c++
#include "ca/buffering.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/io.hpp"
#include "ca/print.hpp"
#include "ca/sv.hpp"
#include "ca/writer.hpp"

auto main(void) -> int {
	auto ends = ca::sys::pipe(ca::fs::cloexec_t::OPEN_VALUE);
	if (!ends)
		return 1;
	char buffer[64];
	ca::io::writer out{ends->write_end(), ca::io::buffering::full, buffer};
	if (!ca::print(out, "x={} ", 1) || !ca::print(out, "y={}\n", 2) || out.pending() != 8U)
		return 2;
	if (!out.flush() || out.pending() != 0U)
		return 3;

	char got[16];
	auto n = ca::sys::read(ends->read_end(), got);
	if (!n || ca::sv::str{got, *n} != ca::sv::str{"x=1 y=2\n"})
		return 4;

	auto direct = ca::io::writer::unbuffered(ends->write_end());
	if (!ca::print(direct, "now\n") || !ca::sys::read(ends->read_end(), got))
		return 5;
	return ca::sys::close(ends->read_end()) && ca::sys::close(ends->write_end()) ? 0 : 6;
}
```

### Readers

An `io::reader` is a buffered reader (`io::is_buffered_reader`): `fill()` and `consume(n)` let a parser work inside the buffer, `read_until(delimiter)` returns the next delimited run in place, and `read_line` / `read_to_end` (layer 5) copy out of it. A reader can be tied to a writer (`tie`), whose pending output is written before each read that may block, so a prompt shows before input is awaited; `io::in()` is tied to the calling thread's `io::out()` that way.

`io::stream` pairs a reader and a writer over one descriptor (a socket, a terminal) or two (a pipe pair), the reader tied to the writer, so a request is sent before the reply is awaited.

```c++
#include "ca/buffering.hpp"
#include "ca/file.hpp"
#include "ca/format_to.hpp"
#include "ca/io.hpp"
#include "ca/stream.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto requests = ca::sys::pipe(0);
	auto replies = ca::sys::pipe(0);
	if (!requests || !replies)
		return 1;
	char input[32];
	char output[32];
	ca::io::stream s{replies->read_end(), requests->write_end(), ca::io::buffering::full, input, output};
	if (!ca::format_to(s, "ping {}\n", 1) || s.pending() != 7U)
		return 2;
	if (!ca::sys::write(replies->write_end(), ca::sv::str{"pong 1\n"}))
		return 3;

	auto answer = s.read_until('\n');
	if (!answer || *answer != ca::sv::str{"pong 1\n"} || s.pending() != 0U)
		return 4;
	char sent[16];
	auto n = ca::sys::read(requests->read_end(), sent);
	if (!n || ca::sv::str{sent, *n} != ca::sv::str{"ping 1\n"})
		return 5;
	return ca::sys::close(requests->read_end()) && ca::sys::close(requests->write_end())
		&& ca::sys::close(replies->read_end()) && ca::sys::close(replies->write_end()) ? 0 : 6;
}
```

### Owned buffers

`buffered_writer<A>` and `buffered_reader<A>` own their buffer, from allocator A, and can own their descriptor too: `over(fd, ...)` borrows it, `adopt(descriptor, ...)` takes an `fs::descriptor` and closes it in `cleanup()`. Both are `make`, which picks by the argument (a borrowed fd or `const fs::descriptor&`, a moved `fs::descriptor&&`), as `ca::make` and `ca::make_in` call it. `resize(capacity)` swaps the buffer (0 makes a writer unbuffered). `writer()` and `reader()` give the inner object for code that takes an `io::writer&` or `io::reader&`.

```c++
#include "ca/buffered_writer.hpp"
#include "ca/buffering.hpp"
#include "ca/descriptor.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/print.hpp"
#include "ca/utility.hpp"

auto main(void) -> int {
	auto file = ca::fs::descriptor::open("log.tmp", ca::fs::writable | ca::fs::create | ca::fs::truncate, 0644U);
	if (!file)
		return 1;
	auto log = ca::io::buffered_writer<>::adopt(ca::move(*file), ca::io::buffering::line, 4096U);
	if (!log || !log->owns_descriptor())
		return 2;
	for (int i = 0; i < 3; ++i)
		if (!ca::print(log->writer(), "event {}\n", i))
			return 3;
	return log->cleanup() && ca::sys::unlink("log.tmp") ? 0 : 4;
}
```

### Standard streams

`io::out()` is this thread's standard output: a 4 KiB buffer, line policy on a terminal and full otherwise, opened on first use, flushed when the thread exits and, for the thread that calls `exit` (returning from `main` included), at exit; `exit_immediately` and crashes drop it. Being per thread, it needs no lock, and each message reaches fd 1 whole. `io::err()` is unbuffered: each message is one write as it happens. `io::in()` is the process's standard input, one per process, so read it from one thread at a time.

## `io/reader.hpp`

Buffered input from a file descriptor.

Performance:

- Layout: four pointers (buffer begin, read cursor, end of data, end of buffer), the fd and a tied writer pointer; 48 bytes on 64-bit. The buffer is borrowed, never allocated. Trivially destructible: nothing to flush on input.

## `io/writer.hpp`

Buffered output to a file descriptor.

Performance:

- Layout: three pointers (buffer begin, fill cursor, end), the fd, the policy and the sticky error; 40 bytes on 64-bit. The buffer is borrowed, never allocated: the caller (or the per-thread standard writers) owns it.
- Formatting writes straight into the buffer through window()/drain()/settle(): no staging copy. write() is one bounds check and a memcpy while the bytes fit.
- Slow paths (writing out, writes larger than the buffer) are out of line and take the fd and pointers, never `this`, so callers keep the cursor in a register.
- Writes larger than the whole buffer bypass it: pending bytes first, then the data directly, two write calls and no copy.
- line policy scans only the bytes of the current message for '\n' (memchr).
- A writer without a buffer (unbuffered(fd)) has an empty window: print stages each message on its stack (1 KiB) and writes it with one call.
- A failed write-out moves the bytes not written to the front of the buffer (memmove), error path only.

### class `writer`

```c++

```

Writer over a file descriptor it does not own, buffering into memory the caller provides, with a policy (ca::io::buffering). Each call returns its own error, and the first one since the last check is kept, sticky: error() peeks, clear_error() forgets it once handled, flush() returns and clears it. When writing out fails, the bytes not written stay pending, never retried behind the caller's back: flush() retries them, discard() drops them; a message still being formatted is dropped whole unless part of it already went out. Cleanup is flush(); the destructor is a failsafe that writes out pending bytes silently. Not thread-safe: one writer per thread (ca::io::out() is).

Over file's descriptor (a ca::fs::descriptor, or anything with native() -> int), borrowed: file must stay open while the writer writes.

### function `writer::unbuffered`

```c++
[[nodiscard]] static auto unbuffered(const int fd) noexcept -> self;
```

No buffer: each message is one write (print stages it), each write() too.

### function `writer::buffer`

```c++

```

The whole buffer; empty when unbuffered.

### function `writer::pending`

```c++
[[nodiscard]] constexpr auto pending(void) const noexcept -> ca::usz;
```

Bytes buffered, not yet written out (including those a failed write-out kept).

### function `writer::error`

```c++
[[nodiscard]] constexpr auto error(void) const noexcept -> ca::error;
```

The sticky error, ok when none; kept until flush() or clear_error().

### function `writer::write`

```c++
[[nodiscard]] auto write(const ca::span<const ca::byte> data) noexcept -> ca::result<void>;
```

Appends data, then applies the policy to it; fails when that writes out and the write fails, data then pending. Data that does not fit is refused when writing out the pending bytes fails. Data larger than the buffer goes out directly: on failure, what was not written is lost.

### function `writer::write_pending`

```c++
[[nodiscard]] auto write_pending(void) noexcept -> ca::result<void>;
```

Writes pending bytes out; this write-out's error, also kept sticky. What a reader tied to this writer calls before it blocks.

### function `writer::flush`

```c++
[[nodiscard]] auto flush(void) noexcept -> ca::result<void>;
```

Writes pending bytes out, then returns the sticky error (this write-out's when it is the first) and clears it.

### function `writer::clear_error`

```c++
constexpr auto clear_error(void) noexcept -> void;
```

Forgets the sticky error, once handled, so flush() does not report it again.

### function `writer::discard`

```c++

```

Drops the pending bytes, unwritten.

### function `writer::set_buffer`


Writes pending bytes out, then buffers into buffer instead (empty: unbuffered); bytes a failed write-out kept move along when they fit, else are lost. Returns the write-out's error. The old buffer is free once this returns.

### function `writer::set_buffering`

Changes the policy; none writes pending bytes out now, returning that error.

### function `writer::window`

### function `writer::drain`

## `print/`

Printing: the formatting of layer 5 aimed at standard output, standard error or any writer.

| Function | Does |
|---|---|
| `ca::print("...", args...)` | `{}` syntax to this thread's stdout (`io::out()`) |
| `ca::print(writer, "...", args...)` | the same to any writer: `io::err()`, a file, a string |
| `ca::printf("%...", args...)` | C's `%` syntax, typed and checked at compile time, no varargs |
| `ca::flush()` | writes out stdout and returns the first error since the last flush |
| `ca::print_trace(error)` | an error and its trace, to `io::err()` or a given writer |

The format is checked when the program compiles, like every format of ca: a placeholder that does not fit its argument, or a missing argument, does not build. Each call returns the size of its message in bytes, or its error; the writer also keeps the first error sticky, so a program can print freely and check once with `ca::flush()` before it exits.

```c++
#include "ca/error.hpp"
#include "ca/flush.hpp"
#include "ca/memory_writer.hpp"
#include "ca/print.hpp"
#include "ca/print_trace.hpp"
#include "ca/printf.hpp"
#include "ca/result.hpp"
#include "ca/sv.hpp"
#include "ca/trace.hpp"

[[nodiscard]] static auto open_config(void) noexcept -> ca::result<int> {
	return ca::trace::fail(ca::errc::no_entry, "app.toml");
}

auto main(void) -> int {
	const char* const names[] = {"ada", "grace"};
	const double ratios[] = {0.5, 0.875};
	for (int i = 0; i < 2; ++i)
		if (!ca::printf("%-8s|%5.2f\n", names[i], ratios[i]))
			return 1;
	if (!ca::print("{} items, {:.0f}% done\n", 2, 50.0))
		return 2;
	if (!ca::flush())
		return 3;

	auto config = open_config();
	if (config)
		return 4;
	char buffer[256];
	ca::io::memory_writer report{buffer};
	if (!ca::print_trace(report, config.error()))
		return 5;
	return report.view().starts_with("No such file or directory\n  at open_config (") ? 0 : 6;
}
```

`ca::print_trace(error)` writes the error's message and, when it carries the thread's current trace, one line per frame:

```text
No such file or directory
  at open_config (main.cpp:12): app.toml
```

A `ca::report` (layer 5) prints the same way with `ca::print("{}\n", report)`.

`io::out()` is buffered per thread and flushed at thread exit and at `exit`, but that failsafe ignores errors: call `ca::flush()` to learn whether everything was written (a full disk, a closed pipe). Printing to `io::err()` writes immediately, unbuffered.

## `trace/`

`ca::trace::symbolizer`: turns the addresses of a `ca::trace::backtrace` (layer 3) into function names, source files and lines, reading the running executable's own symbol tables and DWARF debug information, without libc or external tools.

```c++
#include "ca/symbolizer.hpp"
#include "ca/trace.hpp"

[[gnu::noinline]] static auto where(void) noexcept -> ca::trace::backtrace {
	return ca::trace::backtrace::capture();
}

auto main(void) -> int {
	const ca::trace::backtrace here = where();
	auto symbols = ca::trace::symbolizer::make();
	if (!symbols)
		return 1;
	ca::trace::location found[ca::trace::location::SCOPES];
	const ca::usz count = symbols->lookup(here.addresses()[0], found);
	if (count == 0U || !found[count - 1U].function().find(ca::sv::str{"where"}).holds())
		return 2;
	return symbols->cleanup() ? 0 : 3;
}
```

`lookup(address, out)` writes the functions an address is in, innermost first: the functions the compiler inlined there, then the function they were inlined into, which also carries the offset from its start. Printed with `{}`, `symbols.of(backtrace.addresses())` reads:

```text
#0 ca::trap (/src/lib/1-primitives/debug/trap.hpp:23) inlined
   deepest+0x1e (/src/test.cpp:8)
#1 middle+0x9 (/src/test.cpp:14)
#2 0x7f3c2a42a1c9
```

| Built with | Names | File and line | Inlined functions |
|---|---|---|---|
| `-g` | from DWARF, qualified (`ca::trap`) | yes | yes |
| no `-g` | from the symbol table, mangled (`_ZL7deepestv`) | no | no |
| stripped | none | no | no |

DWARF 4 and 5 are read (clang and gcc defaults), including indexed strings, addresses and range lists; compressed debug sections (`-gz`) and split DWARF (`-gsplit-dwarf`) are not. Names are not demangled: DWARF names need no demangling, symbol-table names stay mangled. Shared objects ca's own loader (`ca::dl`) holds when make() runs are read as well, from their files; addresses in libraries libc's loader mapped (libc itself) are not found and print as they are, and so are those of libraries loaded after make().

make() maps the whole executable read-only, and each of those shared objects; names, files and lines borrow from those mappings until cleanup(), even after a library is released. A lookup scans the unit holding the address entry by entry, so it is for reports, not hot paths.

## `trace/impl/`

The symbolizer's internals. `mapped_image` is one ELF file it mapped: its sections (`trace::impl::debug_image`, layer 3) and where its code runs, as a bias and an address range. The executable is one, every shared object ca's loader held when the symbolizer was made is another.

`loaded_objects` is how the symbolizer learns of those objects without depending on the loader: an atomic pointer to a function visiting each of them (`loaded_object`: path, device and inode, bias, range), null until `ca::dl` loads something. The symbolizer maps each file again by its path and keeps it only when its device and inode still match, so a file replaced since it was loaded is left out rather than read wrong.
