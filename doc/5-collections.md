### The rules every collection follows

- Allocator as a template parameter, `A = ca::heap` by default: `dynamic_array<int, arena_allocator>` lives in an arena; `ca::make_in` builds one over any allocator or resource.
- Construction allocates nothing and cannot fail. Everything that acquires memory (`append`, `reserve`, `insert`, `clone`, ...) returns a `ca::result` the caller must look at.
- `cleanup()` releases the memory and cleans up the elements that are themselves cleanable, returning the first failure. The destructor is only a failsafe.
- No copy constructor where copying allocates: `clone()` returns a `result`.
- `operator[]` traps out of range, in every build; `get(i)` returns an optional for an index that may be out of range. Removing functions (`pop`, `remove`) return optionals.
- The API follows Python where it fits: `append`, `extend`, `pop`, `insert`, `remove`, `count`, `find`; strings have the str methods, maps the dict ones.
- Element sequences share the slice methods of `borrowed_slice` (layer 2): `prefix`, `sub`, `find`, `contains`, `count`, `reverse`, `fill`, `==`; strings share the text methods of `sv`.

```c++
#include "ca/dynamic_array.hpp"
#include "ca/format.hpp"
#include "ca/hashmap.hpp"
#include "ca/str.hpp"

auto main(void) -> int {
	ca::dynamic_array<int> scores{};
	if (!scores.extend({70, 85, 92}) || !scores.append(64))
		return 1;
	ca::hashmap<ca::str, int> best{};
	if (!best.set("ada", scores[2]) || !best.set("bob", scores.first().value_or(0)))
		return 2;
	auto line = ca::format("{} players, best {}", best.size(), best["ada"]);
	if (!line || *line != ca::sv::str{"2 players, best 92"})
		return 3;
	return scores.cleanup() && best.cleanup() && line->cleanup() ? 0 : 4;
}
```

## `array/`

Contiguous and ring containers. Pick by where the elements live and whether the size changes:

| Type | Storage | Size | Counterpart |
|---|---|---|---|
| `dynamic_array<T, A>` | one block from A | grows | Python's list, `std::vector` |
| `array<T, N>` | inline | fixed N | `std::array` |
| `inline_array<T, N>` | inline | up to N, `errc::no_space` past it | `std::inplace_vector` |
| `small_array<T, N, A>` | first N inline, then a block from A | grows | LLVM's SmallVector |
| `slice<T, A>` | one block from A | fixed at creation | Rust's `Box<[T]>` |
| `deque<T, A>` | a power-of-two ring from A | grows at both ends | `collections.deque` |
| `bit_array<N>` | inline words | fixed N bits | `std::bitset` |
| `dynamic_bit_array<A>` | words from A | grows | `std::vector<bool>`, done right |

### dynamic_array

The everyday container. Three pointers wide (plus a stateful allocator), it grows by doubling and relocates elements with one memcpy when T is trivially relocatable, which includes ca's own owning types.

```c++
#include "ca/dynamic_array.hpp"
#include "ca/slice.hpp"
#include "ca/utility.hpp"

auto main(void) -> int {
	ca::dynamic_array<int> values{};
	if (!values.reserve(8U) || !values.extend({5, 3, 8}) || !values.append(1))
		return 1;
	if (!values.insert(1U, 9) || values[1] != 9 || values.size() != 5U)
		return 2;

	if (values.pop().value_or(0) != 1 || values.pop(0U).value_or(0) != 5)
		return 3;
	if (values.remove(8).value_or(0) != 8 || values.remove(42))
		return 4;
	if (values.size() != 2U || values.find(3).value_or(9U) != 1U || values.get(2U))
		return 5;

	if (!values.resize(6U, 7) || values.count(7) != 4U)
		return 6;
	values.view().sub(2U, 2U).fill(0);
	values.reverse();
	if (values[0] != 7 || values.last().value_or(0) != 9)
		return 7;

	auto copy = values.clone();
	if (!copy || !(*copy == values))
		return 8;
	ca::slice<int> fixed = ca::move(*copy).into_slice();
	return fixed.size() == 6U && fixed.cleanup() && values.cleanup() ? 0 : 9;
}
```

`append(a[0])` is safe even when it reallocates: the element is copied before the old block goes. `swap_pop(i)` removes in O(1) by moving the last element into the hole. `into_slice()` hands the block to a `slice` without copying, trimmed to size. Range-for, `data()` and `size()` work as usual; `view()` gives the `borrowed_slice` for cutting.

### Fixed and inline storage

`ca::array<T, N>` is a plain aggregate (CTAD: `ca::array{1, 2, 3}`), constexpr, with the slice methods and `cleanup()`/`clone()` when T has them. `inline_array<T, N>` has the `dynamic_array` API over inline storage: never allocates, fails with `errc::no_space` instead. `small_array<T, N, A>` keeps the first N elements inline and spills to the heap past them; it is not trivially relocatable while inline, since its pointer points into itself.

```c++
#include "ca/array.hpp"
#include "ca/error.hpp"
#include "ca/inline_array.hpp"
#include "ca/small_array.hpp"

constexpr auto sorted3(ca::array<int, 3> a) noexcept -> ca::array<int, 3> {
	if (a[0] > a[1])
		ca::swap(a[0], a[1]);
	if (a[1] > a[2])
		ca::swap(a[1], a[2]);
	if (a[0] > a[1])
		ca::swap(a[0], a[1]);
	return a;
}

static_assert(sorted3(ca::array{3, 1, 2}) == ca::array{1, 2, 3});

auto main(void) -> int {
	ca::inline_array<int, 4> few;
	if (!few.extend({1, 2, 3, 4}) || !few.full())
		return 1;
	auto overflow = few.append(5);
	if (overflow || overflow.error() != ca::errc::no_space)
		return 2;

	ca::small_array<int, 4> mostly_small;
	if (!mostly_small.extend({1, 2, 3}) || !mostly_small.is_inline())
		return 3;
	if (!mostly_small.extend({4, 5}) || mostly_small.is_inline())
		return 4;
	return mostly_small.cleanup() ? 0 : 5;
}
```

### slice and deque

A `slice<T, A>` is an owned run of fixed length: `make(n, args...)` builds n elements from args, `make(view)` copies a view. A `deque<T, A>` is a ring buffer with O(1) `append`, `prepend`, `pop` and `pop_front`; `as_slices()` exposes its contents as the two contiguous runs of the ring.

```c++
#include "ca/borrowed_slice.hpp"
#include "ca/deque.hpp"
#include "ca/slice.hpp"

auto main(void) -> int {
	auto sevens = ca::slice<int>::make(4U, 7);
	if (!sevens || sevens->count(7) != 4U)
		return 1;
	const int raw[] = {4, 3, 2, 1};
	auto copied = ca::slice<int>::make(raw);
	if (!copied || !(*copied == ca::borrowed_slice{raw}))
		return 2;

	ca::deque<int> queue;
	for (int i = 0; i < 5; ++i)
		if (!queue.append(i))
			return 3;
	if (!queue.prepend(-1) || queue.pop_front().value_or(0) != -1 || queue.pop().value_or(0) != 4)
		return 4;
	const auto runs = queue.as_slices();
	if (runs[0U].size() + runs[1U].size() != 4U || queue.first().value_or(9) != 0)
		return 5;
	return sevens->cleanup() && copied->cleanup() && queue.cleanup() ? 0 : 6;
}
```

### Bits

`bit_array<N>` and `dynamic_bit_array<A>` pack bits into 64-bit words and work a word at a time: `count`, `any`, `all`, `none`, `find_first`, `find_next`, `find_first_unset`, iteration over the set bits with `ones()`, and `&=`, `|=`, `^=` between arrays of the same size. `ones()` is a view into the array: call it on a named array, not on a temporary, which would be gone before the loop runs.

```c++
#include "ca/bit_array.hpp"
#include "ca/dynamic_bit_array.hpp"
#include "ca/integers.hpp"

constexpr auto primes_below_32(void) noexcept -> ca::bit_array<32> {
	ca::bit_array<32> sieve;
	sieve.set_all();
	sieve.reset(0U);
	sieve.reset(1U);
	for (ca::usz i = 2U; i * i < 32U; ++i)
		if (sieve[i])
			for (ca::usz j = i * i; j < 32U; j += i)
				sieve.reset(j);
	return sieve;
}

static_assert(primes_below_32().count() == 11U);
static_assert(primes_below_32().find_next(14U).value_or(0U) == 17U);

auto main(void) -> int {
	const ca::bit_array<32> primes = primes_below_32();
	ca::usz sum = 0U;
	for (const ca::usz p : primes.ones())
		sum += p;
	if (sum != 160U)
		return 1;
	auto flags = ca::dynamic_bit_array<>::make(100U, false);
	if (!flags || !flags->append(true) || flags->count() != 1U || flags->find_first().value_or(0U) != 100U)
		return 2;
	return flags->cleanup() ? 0 : 3;
}
```

`ca::collect(range)` gathers any range into a new `dynamic_array`, Python's `list(range)`: the pieces of a split, the keys of a map.

## `array/array.hpp`

Performance of ca::array<T, N>.

Layout: N elements in the object itself, nothing else: sizeof(array<T, N>) is N * sizeof(T), alignment alignof(T). No pointer, no size, no allocation; array<T, 0> is empty.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare against the constant N; folds away for constant indices |
| size, empty, begin, end, data, view | O(1) | size() is a constant expression |
| construction | O(N) | value-initialized, or from N values; constexpr |
| find, count, contains, compare, == | O(N) | memchr/memcmp for code units, element loops otherwise |
| fill, reverse | O(N) | |
| cleanup, clone | O(N) | only for cleanable and clonable T |

Space: exactly the elements. Locality and alignment: contiguous, stride sizeof(T), wherever the array lives (stack, inside another object, static storage); scans vectorize and the bounds are known to the compiler.

Copy and move: those of T, element by element; trivially copyable when T is, then copied as bytes and usable in constant expressions. TRIVIALLY_RELOCATABLE when T is.

Inlining: every member is a constexpr inline one-liner over the built-in array.

Against std::array: same layout and code; operator[] checks its index in every build (std only with assertions enabled), the check disappearing when the index is a constant or bounded by size().

## `array/bit_array.hpp`

Performance of ca::bit_array\<N>.

Layout: ceil(N / 64) words of 64 bits in the object itself, nothing else: bit_array<100> is 16 bytes, bit_array<512> 64. No pointer, no size, no allocation; trivially copyable, usable in constant expressions.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, set, reset, flip | O(1) | one compare against N, a shift and a mask |
| count | O(N / 64) | one popcount per word (popcnt with -mpopcnt or -march) |
| any, none, all | O(N / 64) | stops at the first word that decides |
| find_first, find_next, and their unset forms | O(N / 64) | one countr_zero on the first non-empty word |
| ones() walk | O(N / 64 + set bits) | clears the lowest bit per step |
| set_all, reset_all, flip_all, &=, |=, ^=, == | O(N / 64) | word loops; vectorize |

Space: N bits rounded up to 64. Locality: one contiguous run of words.

Against std::bitset: same layout and complexities; adds find_next/find_next_unset (std has none; libstdc++'s _Find_next is an extension), the ones() range, traps on bad indices in every build, and allocation-free constexpr throughout.

Baseline std::bitset<65536>; ca is bit_array<65536>: bench/bit_array.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| count 64 Ki bits, 2e3 times | 1.03x | 1.04x | |
| scan a sparse set with find_first/find_next, 2e2 times | 1.16x | 1.00x | std: libstdc++'s _Find_first/_Find_next |

## `array/deque.hpp`

Performance of ca::deque<T, A>.

Layout: a pointer to a ring of capacity() slots and three integers (head slot, size, capacity), 32 bytes on 64-bit, plus the allocator: nothing for a stateless one (ca::heap, the default). Capacity is a power of two, so element i lives at (head + i) & (capacity - 1): one add and one and, no division, no branch. An empty deque owns no memory.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare, one add, one and |
| size, capacity, empty, begin, end | O(1) | |
| append, emplace, prepend, emplace_front | amortized O(1) | O(n) on the growth step |
| pop, pop_front | O(1) | one emptiness compare |
| extend(view) | amortized O(n) | at most two memcpy for trivially copyable T |
| reserve | O(n) | trivially relocatable T: ca::reallocate, then the shorter run (at most half) moves once |
| shrink, clone | O(n) | elements laid out from slot 0 |
| clear, cleanup | O(n) | O(1) for trivially destructible T without cleanup() |
| as_slices | O(1) | the two contiguous runs, front first |
| find, count, contains | O(n) | over the two runs |

Space: capacity doubles, the first allocation holds 4 elements; capacity is the power of two asked for, so up to 2x the live elements after growth (plus the allocator's rounding, unused). shrink() brings it to the power of two at or above size().

Locality and alignment: elements are contiguous in at most two runs (as_slices); a queue that never holds more than capacity() elements cycles through one block forever, with no allocation and no shifting. Iteration masks each index; loops over as_slices() vectorize.

Relocation: growth by ca::reallocate (trivially relocatable T) or expand leaves the block's contents in place and relocates only the shorter run: the wrapped one past the old capacity, or the front one to the end of the new block. One memcpy of at most half the elements. A fresh block takes both runs at those same offsets. Other types are move-constructed and destroyed one by one.

Aliasing: unlike dynamic_array, which stores pointers, the head and size are integers; a store of usz-sized integer elements may make the compiler reload them. Growth builds the new element before the block moves, so `d.append(d[0])` stays valid; a failed growth changes nothing.

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy. Move construction and assignment take four words and the allocator, noexcept, no allocation. TRIVIALLY_RELOCATABLE when A is.

Inlining: append, prepend, pop, pop_front and operator[] are a handful of instructions; growth runs in out-of-line static helpers that receive pointers, sizes and the allocator by value.

Against std::deque (a map of fixed 512-byte blocks): one block instead of one per 512 bytes and a map, element access without the two-level lookup, contiguous runs for bulk work. std::deque never moves elements on growth, which keeps references stable; ca::deque does not promise that.

Baseline std::deque; ca over ca::heap: bench/deque.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| append 1e7 ints, growing | 0.34x | 0.24x | |
| prepend 1e7 ints, growing | 0.56x | 0.83x | |
| FIFO 1e3 deep, 1e7 append + pop_front | 0.50x | 0.28x | |
| both ends, 1e7 u64 | 0.74x | 0.56x | |
| operator[] sum, 1e6 ints x 10 | 0.30x | 0.37x | one mask per index; std: a block lookup |
| range-for sum, 1e6 ints x 10 | 0.67x | 0.71x | |

Growth must stay a static out-of-line helper fed by value: a member call passing `this` kept every field in memory (1.3x slower than std on clang), and inlining the whole growth path made clang stop inlining emplace (3x slower).

### class `deque`

```c++
template <typename T, ca::is_allocator A = ca::heap>
class deque final;
```

Growable double-ended queue of T in one ring of memory from A: Python's collections.deque, Rust's VecDeque. append/prepend and pop/pop_front in O(1) at both ends, operator[] in O(1). Construction allocates nothing; reserve, append, prepend, extend, shrink and clone acquire memory and can fail, changing nothing then. Elements live in at most two contiguous runs (as_slices). Clean up with cleanup(); the destructor is a failsafe that frees silently. operator[] traps out of range; get allows the doubt. A stateful A has no default construction and moves with the elements.

## `array/dynamic_array.hpp`

Performance of ca::dynamic_array<T, A>.

Layout: three pointers (data, end, limit), 24 bytes on 64-bit, plus the allocator: nothing for a stateless one (ca::heap, the default), its size for a stateful one (8 for arena_allocator). Empty arrays own no memory. Pointers instead of size/capacity integers: under strict aliasing, storing an integer element cannot clobber a pointer member, so end stays in a register across pushes and index loops (char/byte elements still alias everything). size() and capacity() cost a subtraction and a shift, or a multiply for sizes that are not powers of two.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare; in `i < size()` loops it folds into the loop bound |
| size, capacity, empty, begin, end, data | O(1) | |
| append, emplace | amortized O(1) | O(n) on the growth step |
| extend(view) | amortized O(n), one memcpy for trivial T | O(size + n) on the growth step |
| pop() | O(1) | one emptiness compare (std::vector::pop_back has none) |
| insert(i), pop(i) | O(n - i) | one memmove for trivially relocatable T |
| insert(i, view) | O(n - i + m) | one memmove and one memcpy for trivial T |
| remove(value) | O(n) | find, then pop(i) |
| swap_pop(i) | O(1) | the last element relocates into the hole; order not kept |
| reserve, shrink | O(n) | trivially relocatable T: ca::reallocate (heap: in place within a size class, page remap past 128 KiB, no copy); others try expand first |
| resize(n) | O(abs(n - size)) | plus the growth step |
| clear, cleanup | O(n) | O(1) for trivially destructible T without cleanup() |
| clone | O(n) | one memcpy for trivially copyable T |
| view, prefix, suffix, sub | O(1) | borrowed_slice: two words, no allocation |
| find, count, contains, compare, == | O(n) | memchr/memcmp for code units, element loops otherwise |
| into_slice | O(1) | the block changes owner, no copy |

Space: capacity doubles, the first allocation holds 4 elements, and capacity is the allocator's usable size: the heap rounds to its size class (at most 25% over past 128 bytes), so up to 2.5x the live elements after growth. shrink() trims to the allocator's rounding. Up to 4 elements cost one allocation (std::vector grows 1, 2, 4).

Locality and alignment: elements are contiguous in index order with stride sizeof(T), in a block aligned to alignof(T) (the heap gives 16 at least, more on request). Linear scans are prefetcher-friendly and vectorize, through iterators or indices. The header lives apart from the elements.

Relocation: growth, shrink, insert and remove move elements by relocation. For trivially copyable T, and for types opting in with TRIVIALLY_RELOCATABLE (dynamic_array itself), that is memcpy/memmove, and reserve/shrink use ca::reallocate; an outer array never touches its inner arrays' blocks. Other types are move-constructed and destroyed one by one, in a single pass.

Growth and aliasing: appending a T (or nothing) to a full array of trivially copyable T copies the value first, then reallocates; `a.append(a[0])` stays valid. Other arguments are built into the new block before the old one is released. Either way a failed growth changes nothing.

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy, in the same allocator (clone_in for another). Move construction and assignment take three pointers and the allocator, noexcept, no allocation. Not trivially copyable (destructor failsafe): passed and returned through memory, so take it by reference and return it by value (NRVO, result<dynamic_array>).

Inlining: the fast paths (append, emplace, operator[], pop) are a handful of instructions. Growth runs in out-of-line static helpers that receive pointers, sizes and the allocator by value, never `this` nor a reference to the allocator member: the caller's array is not address-taken, its members stay in registers. Inlining the heap's fast path there instead cost 5x on append/pop churn with gcc.

Cleanup: cleanup() and clear() run each element's cleanup() and destructor in one pass.

Baseline std::vector (std::allocator over glibc malloc); ca over ca::heap (heap) and over glibc malloc through ca::libc_allocator (libc), which isolates the container from the allocator: bench/dynamic_array.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

Performance of ca::inline_array<T, N>.

Layout: the size (a usz), then room for N elements, in the object itself: no pointer, no allocation, no indirection. inline_array<int, 16> is 72 bytes, inline_array<u64, 4> 40. Slots past size() are raw storage: nothing is constructed there. The size is a full word on purpose: a u8 size made append/pop churn 2x slower with clang (partial-register updates in the loop-carried chain), for 7 bytes saved.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare against size() |
| size, empty, full, begin, end, data, view | O(1) | capacity() is a constant expression |
| append, emplace | O(1) | one compare against N, no growth path |
| extend(view) | O(n) | one memcpy for trivially copyable T |
| insert(i), pop(i) | O(size - i) | one memmove for trivially relocatable T |
| swap_pop(i), pop() | O(1) | |
| remove(value) | O(size) | find, then pop(i) |
| resize, clear, cleanup | O(abs(n - size)) | O(1) for trivially destructible T without cleanup() |
| clone, make(view) | O(n) | one memcpy for trivially copyable T |
| find, count, contains, compare, == | O(n) | memchr/memcmp for code units, element loops otherwise |

Nothing grows: what does not fit fails with errc::no_space and changes nothing. That is the point of it: bounded memory known at compile time, never a failed allocation, a place on the stack or inside another object for short lists of non-trivial elements (a function's arguments, a node's children, the last N events).

Locality and alignment: the elements follow the size in one block aligned to alignof(T); reading one reaches the same cache lines as the object itself.

Copy and move: trivially copyable when T is (copied as bytes, all N slots); otherwise copy is deleted, clone() is the explicit copy, and moving relocates the live elements and leaves the source empty. TRIVIALLY_RELOCATABLE when T is.

Against std::vector with reserved capacity, at most N elements: no heap round trip at construction and destruction, append is one compare and one store. C++26 std::inplace_vector is the same structure.

## `array/slice.hpp`

Performance of ca::slice<T, A>.

Layout: three pointers (data, end, and the end of the block, which the allocator needs back), 24 bytes on 64-bit, plus the allocator: nothing for a stateless one (ca::heap, the default). An empty slice owns no memory. The length is fixed at creation; there is no spare capacity to grow into, so nothing but the elements is ever constructed.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare |
| size, empty, begin, end, data, view | O(1) | |
| make(n, args...), make(view), clone | O(n) | one allocation; one memcpy for trivially copyable T in make(view) and clone |
| into_slice (dynamic_array) | O(1) | takes the array's block as is, no copy, no shrink |
| find, count, contains, compare, == | O(n) | memchr/memcmp for code units, element loops otherwise |
| find(other), find_last(other) | O(n * m) | |
| fill, reverse | O(n) | |
| cleanup | O(n) | O(1) for trivially destructible T |

Space: the block the allocator returns for n elements (the heap rounds to its size class), nothing else. A slice from dynamic_array::into_slice keeps the array's capacity.

Locality and alignment: elements are contiguous in index order with stride sizeof(T), in a block aligned to alignof(T); scans vectorize. The header lives apart from the elements.

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy (clone() of each element when T has one). Move construction and assignment take three pointers and the allocator. TRIVIALLY_RELOCATABLE when A is: containers move slices with memcpy.

Inlining: element access and the slice methods are inline; allocation goes through ca::allocate_n and the allocator's own fast path.

Cleanup: cleanup() runs each element's cleanup() and destructor in one pass, then frees.

## `array/small_array.hpp`

Performance of ca::small_array<T, N, A>.

Layout: three pointers (data, end, limit), the allocator (nothing for a stateless one), then room for N elements: small_array<int, 4> is 40 bytes on 64-bit. While size() <= N the elements live in that room and data points into the object; past N they move to a block from A, as in dynamic_array, and the room goes unused until shrink() brings them back.

| Operation | Time | Notes |
|---|---|---|
| operator[], get, first, last | O(1) | one compare; data is a pointer either way, no inline/heap branch |
| size, capacity, empty, is_inline, begin, end, data | O(1) | |
| append, emplace | amortized O(1) | the first N cost no allocation; leaving the inline room is one allocation and one relocation |
| extend(view) | amortized O(n) | one memcpy for trivially copyable T |
| insert(i), pop(i) | O(n - i) | one memmove for trivially relocatable T |
| swap_pop(i), pop() | O(1) | |
| reserve | O(n) | on the heap, trivially relocatable T: ca::reallocate |
| shrink | O(n) | back into the inline room when size() <= N |
| move construction, move assignment | O(1) on the heap, O(size) inline | inline elements are relocated: one memcpy for trivially relocatable T |
| clear, cleanup, clone | O(n) | |
| find, count, contains, compare, == | O(n) | memchr/memcmp for code units, element loops otherwise |

Space: N * sizeof(T) more than dynamic_array, always; growth past N doubles from N, the allocator's rounding included. Pick N as the size most instances never pass: then most instances never allocate.

Locality: inline elements sit next to the header, in the enclosing object or on the stack; a small_array member of a node puts the node's short list in the node's own cache lines.

Relocation: not TRIVIALLY_RELOCATABLE, since data points into the object while inline: containers move it with its move constructor, which re-points data. Elements move as in dynamic_array.

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy, inline when it fits. Moving leaves the source empty and inline.

Inlining: the fast paths (append, emplace, operator[], pop) are those of dynamic_array; growth runs in out-of-line static helpers that receive pointers, sizes and the allocator by value.

Against std::vector: no allocation at all for the first N elements; past N the same costs.

Baseline std::vector\<int> over glibc malloc; ca is small_array<int, 8> over ca::heap: bench/small_arrays.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| 1e6 times build 4 elements (inline) and drop | 0.092x | 0.064x | |
| 1e6 times build 32 elements (leaves the inline room) and drop | 0.43x | 0.40x | |
| churn, 1e7 appends, popping all at 8 | 0.82x | 1.57x | gcc: vectorized pops stall on store forwarding |

An always-inline growth step keeps `this` from escaping; without it clang was 1.03x on the churn.

## `array/impl/`

`bit_methods.hpp`: the bit operations written once for `bit_array<N>` and `dynamic_bit_array<A>`, as a CRTP base over a type exposing its words. Everything works a 64-bit word at a time: `count` is one popcount per word, `find_first` and `find_next` skip zero words and finish with `countr_zero`, `all` and `none` compare whole words, and the bits past the size in the last word are kept zero so that every word-wise answer is right without masking.

`set_bit_iterator` walks the indices of the set bits in increasing order, clearing the lowest bit of a copy of the current word at each step: `for (ca::usz i : bits.ones())` costs one `countr_zero` per set bit, not one test per bit. `bit_words_for(n)` is the number of words holding n bits.

## `concurrent/`

Queues shared between threads: elements go in on one thread and come out on another, in order.

| Type | Threads | Waiting |
|---|---|---|
| `spsc_queue<T, A>` | one producer, one consumer | never: `try_push`, `try_emplace`, `try_pop` |
| `mpmc_queue<T, A>` | any number of each | never: the same three |
| `channel<T, A>` | any number of each | `push`/`pop` sleep while full/empty; `_until`, `_for` and `try_` variants; `close` |
| `io::spsc_ring_buffer<A>` (in `io/`) | one writer, one reader | never; a byte stream, `format_to` writes into it in place |

All are bounded: the capacity, rounded up to a power of two, is fixed when the factory makes the queue (`make(capacity)`, `make_in(allocator, capacity)`), and nothing allocates after that. None takes a lock. A full queue refuses a push with `errc::no_space` and leaves the argument as it was, so a move-only value is not lost; a pop answers an optional, empty when the queue is. The channel adds sleeping on futexes, `errc::timed_out` for the timed variants, and `errc::broken_pipe` for pushes once closed and for pops once closed and drained.

The queue object is a handle on a block the threads share. Share it by reference; moving it or calling `cleanup()` while another thread may still use it is a bug nothing detects. The single-threaded containers (`deque`, `io::ring_buffer`) stay what they were, with no atomic operation in their way: these types are what to reach for when threads are involved.

```c++
#include "ca/channel.hpp"
#include "ca/error.hpp"
#include "ca/mpmc_queue.hpp"
#include "ca/spsc_queue.hpp"

auto main(void) -> int {
	auto jobs = ca::spsc_queue<int>::make(2U);
	if (!jobs || !jobs->try_push(1) || !jobs->try_push(2))
		return 1;
	auto full = jobs->try_push(3);
	if (full || full.error() != ca::errc::no_space)
		return 2;
	auto first = jobs->try_pop();
	if (!first || *first != 1 || !jobs->cleanup())
		return 3;

	auto shared = ca::mpmc_queue<int>::make(8U);
	if (!shared || !shared->try_emplace(7) || shared->try_pop() != 7 || !shared->cleanup())
		return 4;

	auto results = ca::channel<int>::make(4U);
	if (!results || !results->push(42))
		return 5;
	results->close();
	auto answer = results->pop();
	auto after = results->pop();
	if (!answer || *answer != 42 || after || after.error() != ca::errc::broken_pipe)
		return 6;
	return results->cleanup() ? 0 : 7;
}
```

## `concurrent/channel.hpp`

Performance of ca::channel<T, A>.

- Layout: the handle is a pointer to the block, the cells, the index mask and the allocator (24 bytes with ca::heap). The block holds an mpmc_queue's two claim counters, then the line of the consumers' wait word (an event count bumped when an element arrives, the number of consumers asleep, the closed flag), the producers' line (the mirror, bumped when room appears), then the cells.
- The elements move through the lock-free mpmc ring; blocking only adds sleeping. A thread that finds the ring empty (or full) counts itself as a sleeper, reads the event count, tries once more, and only then sleeps on the count with a futex. The other side, after each element it moves, issues one full fence and reads the sleeper count: the futex wake, a syscall, happens only when a thread actually sleeps. Without waiting, a push or pop costs the mpmc operation plus that fence.
- No lock anywhere, no allocation after the factory; close() wakes every sleeper.
- Time: O(1) per operation besides the waiting; cleanup O(n) for elements left.
- Space: four 128-byte lines and capacity cells, one allocation from A.
- Copy: none; the handle moves (the block stays where it is), but not while shared.

Baseline a std::deque\<T> behind a std::mutex and two std::condition_variable (the textbook bounded buffer); one thread pushing and popping in turn, so nobody ever sleeps and the figures are the cost of the operations themselves:

## `concurrent/mpmc_queue.hpp`

Performance of ca::mpmc_queue<T, A>.

- Layout: the handle is a pointer to the block, the cells, the index mask and the allocator (24 bytes with ca::heap). The block holds the producers' claim counter and the consumers' on separate 128-byte lines, then the cells: a sequence number and room for a T each.
- Dmitry Vyukov's bounded queue: a push claims a position with one compare-exchange on the producers' counter, then publishes through the cell's sequence (one release store); a pop mirrors it on the consumers' counter. Producers never touch the consumers' line, nor the other way round, and two threads meet on a cell only when the queue is near full or empty. No lock: a thread stopped in the middle of an operation delays only the element it claimed.
- Time: try_push, try_emplace, try_pop O(1) besides retries of the compare-exchange under contention; cleanup O(n) for elements left.
- Space: two 128-byte lines and capacity cells (8 bytes plus T, padded to T's alignment), one allocation from A made by the factory; never grows.
- Copy: none; the handle moves (the block stays where it is), but not while shared.

Baseline a std::deque\<T> behind a std::mutex; one thread pushing and popping in turn, the cost of the operations without contention (the harness runs on one CPU):

## `concurrent/spsc_queue.hpp`

Performance of ca::spsc_queue<T, A>.

- Layout: the handle is a pointer to the shared block, the slots, the index mask and the allocator (24 bytes with ca::heap); every thread reads it, none writes it. The block holds the consumer's line (its index and the last producer index it saw), the producer's line (the mirror), then the slots: no line written by both sides.
- Each side reads the other's index only when its cached copy says the queue looks full (producer) or empty (consumer): a stream of pushes and pops makes one acquire load per lap of the other side, not per element. Publishing is one release store, a plain mov on x86: no locked instruction, no fence, on either side.
- Capacity is a power of two: indices are free-running counts masked into the slots.
- Time: try_push, try_emplace, try_pop O(1); cleanup O(n) for elements left.
- Space: two 128-byte lines and capacity slots, one allocation from A (128-byte aligned, or T's alignment when larger), made by the factory; never grows.
- Copy: none; the handle moves (the block stays where it is), but not while shared.

## `concurrent/impl/`

The parts the concurrent queues share.

- `queue_parts.hpp`: `queue_line`, the 128 bytes that keep indices written by different threads apart (x86 fetches cache lines in pairs); `queue_capacity` (a power of two, with a minimum), `queue_layout` / `queue_layout_of` (one block: a header of shared indices, then the slots at their alignment), and `queue_release`, which cleans up and destroys a left element.
- `mpmc_core.hpp`: Vyukov's bounded multi-producer multi-consumer ring as free functions over a borrowed `mpmc_ring` (counters, cells, mask), so `mpmc_queue` and `channel` keep their own block layouts. Each cell's sequence number says whose turn it is: equal to the position, a producer may claim it; position + 1, a consumer may. Claiming is a compare-exchange on the side's counter; publishing is a release store of the next sequence, which is what orders the element's bytes for the other side. Capacity is at least 2: with one cell, full and empty would carry the same sequence.

The channel's waits are event counts over `sys::futex_wait`: a sleeper counts itself, reads the event word, tries the queue once more, then sleeps on that word; the other side, after moving an element, fences and looks at the sleeper count, and only when it is not zero bumps the word and wakes one. Either the sleeper's last try sees the element, or the waker sees the sleeper, so no wake is lost, and an uncontended push or pop makes no syscall.

## `format/`

Formatting, Python's `{}` syntax and C's `%` syntax, both parsed and checked when the program compiles: a placeholder that does not fit its argument, a missing argument or an extra one is a compile error naming the problem. There are no varargs and no runtime parsing.

| Function | Writes into |
|---|---|
| `ca::format("...", args...)` | a new `ca::str`, returned as `result<str>` |
| `ca::format_append(s, "...", args...)` | the end of an existing string (`str`, `basic_str<char, A>`, `inline_str<N>`) |
| `ca::format_to(writer, "...", args...)` | any `io::is_writer`; returns the bytes written |
| `ca::printf_to(writer, "%...", args...)` | the same, with C's `%` syntax |
| `ca::print`, `ca::printf` (layer 6) | standard output |

```c++
#include "ca/error.hpp"
#include "ca/format.hpp"
#include "ca/format_append.hpp"
#include "ca/format_to.hpp"
#include "ca/memory_writer.hpp"
#include "ca/printf_to.hpp"
#include "ca/str.hpp"

auto main(void) -> int {
	auto s = ca::format("{}-{:04} {:.2f} {x}", "id", 42, 3.14159, 255);
	if (!s || *s != ca::sv::str{"id-0042 3.14 ff"})
		return 1;
	if (!ca::format_append(*s, " [{:>4}]", 7) || *s != ca::sv::str{"id-0042 3.14 ff [   7]"})
		return 2;

	char buffer[64];
	ca::io::memory_writer out{buffer};
	auto n = ca::printf_to(out, "%5d|%-4s|%#x", 42, "ab", 255);
	if (!n || out.view() != ca::sv::str{"   42|ab  |0xff"})
		return 3;
	out.clear();
	if (!ca::format_to(out, "{} {d} {?}", ca::errc::no_entry, ca::errc::no_entry, "tab\there"))
		return 4;
	if (out.view() != ca::sv::str{"no_entry 2 \"tab\\there\""})
		return 5;
	return s->cleanup() ? 0 : 6;
}
```

### The `{}` syntax

A placeholder is `{}` or `{spec}` (a leading `:` is allowed, `{:04}` and `{04}` are the same), with spec `[[fill]align][sign][#][0][width][.precision][type]`:

- align `<`, `>` or `^`, after an optional fill character; numbers align right by default, text left
- sign `+` or space; `#` adds the 0x, 0b or 0 prefix; `0` pads numbers with zeros
- width, and the precision of a string, count code points, not bytes
- precision: digits of a float, most code points of a string, fewest digits of an integer
- type: `d x X o b B c` for integers, chars and bools; `s` text; `p` pointers; `f F e E g G a A` floats; `?` quotes and escapes strings and characters, as a debugger shows them
- `{{` and `}}` print one brace

`printf_to` takes `%[flags][width][.precision][length]conversion` with C's meaning, except that the length modifiers are read and ignored (the type is known) and `%s` prints any displayable argument. There is no `*` width and no `%n`.

### What prints

`ca::is_displayable<T>` lists the types: bool, characters, integers, enums (as their integer), `f32` and `f64` (shortest round-trip form by default), C strings, char arrays, views and strings of every code unit type (printed as UTF-8, transcoded when needed, invalid sequences as U+FFFD), anything with `view() -> sv::basic<C>` (`ca::str`, `fs::path`), `ca::error` (its message or errc name; `{d}` the code), pointers, and any type with a `display` member:

```c++
#include "ca/format.hpp"
#include "ca/format_to.hpp"
#include "ca/is_displayable.hpp"
#include "ca/text_writer.hpp"

struct point final {
	int x;
	int y;

	auto display(ca::text_writer& out) const noexcept -> void {
		ca::format_to(out, "({}, {})", x, y);
	}
};

static_assert(ca::is_displayable<point>);

auto main(void) -> int {
	auto s = ca::format("{} -> {}", point{1, 2}, point{3, -4});
	if (!s || *s != ca::sv::str{"(1, 2) -> (3, -4)"})
		return 1;
	return s->cleanup() ? 0 : 2;
}
```

A `display` function writes through the `ca::text_writer` it is given, with `put(char)`, `put(sv::str)`, `fill(c, n)` or a nested `format_to`. It cannot fail itself: when the writer runs out of room or fails, the rest of the message is dropped and the outer call returns the error.

### How it runs

A `format_string<Args...>` is built in a consteval constructor, which parses the literal into pieces and specs and checks them against Args; a bad format calls a function that is never defined, so the compiler reports it at the call. At run time one type-erased engine renders the pieces, so code size does not grow with each format. Writing goes through a `text_writer` straight into the window a windowed writer lends (stdout's buffer, the string's own storage), so formatted text is usually written once, in place.

## `format/format_string.hpp`

### class `format_string`

```c++
template <typename... Args>
class format_string final;
```

A print format for arguments Args, parsed and checked when it compiles: a mismatch is a compile error naming it. Placeholders `{}` or `{spec}` (a leading ':' is allowed), spec being `[[fill]align][sign][#][0][width][.precision][type]`:

- align `<` `>` `^`; default: numbers right, text left; fill a char, default space
- sign `+` or space; `#` adds 0x 0X 0b 0B 0 prefixes; `0` pads numbers with zeros
- width and a string's precision count code points, not bytes
- precision: float digits, max code points of a string, min digits of an integer
- type: d x X o b B c (integers, chars, bools; d also an error's code), s (text), p (pointers), f F e E g G a A (floats), ? (strings and characters quoted and escaped: \t \n \r \0 \\ the quote, other controls \u{..}, invalid UTF-8 bytes \x{..})
- `{{` and `}}` print one brace Text of any code unit prints as UTF-8: char and char8_t as is; char16_t, char32_t and wchar_t characters, pointers, arrays, views and strings transcoded, invalid sequences as U+FFFD. Floats print shortest round-trip by default. Custom types (display member) take `{}` only.

## `format/format_to.hpp`

Formatting into writers: format_to ({}) and printf_to (%), the engine under ca::print.

Performance:

- Formats are parsed and checked at compile time into pieces and specs; nothing is parsed at run time. Arguments are type-erased into 24-byte records, so one out-of-line engine serves every call site: small code per call, no varargs.
- Text is written in place into the writer's window (memory_writer, buffered ca::io::writer); writers without one are staged on a 1 KiB stack buffer.
- Width and precision count code points: ASCII text is checked with a few word loads, anything else decoded. Wide text is transcoded through a 256-byte stack buffer.
- Integers: two digits per division (decimal), shifts for x/o/b. Floats go through ca::sys::format_float (exact digits, no libc); the shortest form is Ryu, a few 128-bit products.

## `format/impl/`

The formatting engine, in two halves: what runs in the compiler, and what runs in the program.

### At compile time

- `parse_braces.hpp`, `parse_printf.hpp`: split a `{}` or `%` format into count + 1 literal `format_piece`s (offset and size in the literal) and count `format_spec`s, inside the consteval constructors of `format_string` and `printf_string`.
- `format_spec.hpp`: one parsed placeholder: fill, align, sign, `#`, zero padding, width, precision and type. Align 0 means the kind's default.
- `display_kind.hpp`: the `display_kind` of each argument type (integer, float, text of each unit size, error, pointer, custom, ...), `none` for a type that cannot print.
- `check_spec.hpp`: rejects a spec the argument kind cannot honour (a precision on a char, `x` on a string, ...).
- `format_errors.hpp`: functions declared and never defined, one per mistake (`format_has_more_placeholders_than_arguments`, `format_type_does_not_fit_the_argument`, `format_has_unmatched_closing_brace`, `printf_conversion_is_unknown`, ...). Calling one in a consteval context is a compile error whose message names the function, which is how a bad format reports what is wrong.

### At run time

- `display_argument.hpp`: each argument erased to a small record (kind, address, size), so the engine is one function, not a template per call site; text of 2- or 4-byte units carries its unit size, a `ca::error` its code and trace number.
- `render.hpp` / `render.cpp`: the engine, shared by `format`, `format_to`, `printf_to`, `print` and `printf`: writes the pieces and arguments through a `text_writer`, padding by code points.
- `emit.hpp`: one message to a writer: rendered in place in the window a windowed writer lends, else through a stack stage handed to `write`; returns the bytes written or the error.

## `fs/`

`ca::fs::path`: a POSIX path after Python's `pathlib.Path`, owning its text (a NUL-terminated block from the allocator, `basic_path<A>`, A = `ca::heap` for `fs::path`).

A path is kept normalized from the moment it is built: no repeated slash, no trailing slash, no "." component ("..", whose meaning depends on symlinks, stays). The empty path is "." and owns no memory. Building or changing a path allocates and returns a `result`; reading its parts returns views into it and cannot fail.

### Lexical operations

These never touch the file system: `name()`, `stem()`, `suffix()`, `parent()`, `root()`, `components()`, `is_absolute()`, `join(other)` (an absolute other replaces the path, as pathlib's `/` does), `push(other)` in place, `with_name`, `with_stem`, `with_suffix`, `relative_to`, `is_relative_to` and `match(pattern)`, a glob matched from the right.

```c++
#include "ca/path.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto p = ca::fs::path::make("//usr/./lib//archive.tar.gz/");
	if (!p || p->view() != ca::sv::str{"/usr/lib/archive.tar.gz"})
		return 1;
	if (p->name() != ca::sv::str{"archive.tar.gz"} || p->stem() != ca::sv::str{"archive.tar"})
		return 2;
	if (p->suffix() != ca::sv::str{".gz"} || p->parent() != ca::sv::str{"/usr/lib"})
		return 3;

	auto zip = p->with_suffix(".zip");
	auto up = p->join("../share");
	if (!zip || zip->view() != ca::sv::str{"/usr/lib/archive.tar.zip"})
		return 4;
	if (!up || up->view() != ca::sv::str{"/usr/lib/archive.tar.gz/../share"})
		return 5;
	if (!p->match("*.tar.*") || !p->match("/usr/*/archive.*") || p->match("/lib/*"))
		return 6;

	int parts = 0;
	for (const ca::sv::str part : p->components())
		parts += part.empty() ? 100 : 1;
	if (parts != 4)
		return 7;
	return p->cleanup() && zip->cleanup() && up->cleanup() ? 0 : 8;
}
```

### File system operations

The others make the system calls their names say: `exists`, `is_file`, `is_directory`, `is_symlink`, `stat`, `lstat`, `mkdir`, `mkdirs` (with parents, existing ones accepted), `rmdir`, `touch`, `unlink`, `rename`, `chmod`, `symlink_to`, `hardlink_to`, `readlink`, `resolve`, `absolute`, `expand_user`, `read_text`, `read_bytes`, `write_text`, `write_bytes`, `iterdir`, `glob` and `rglob` (with `**`). `path::cwd()` and `path::home()` build the working and home directories.

```c++
#include "ca/dynamic_array.hpp"
#include "ca/path.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto root = ca::fs::path::make("path_example");
	if (!root)
		return 1;
	auto deep = root->join("a/b");
	if (!deep || !deep->mkdirs())
		return 2;
	auto file = deep->join("notes.txt");
	if (!file || !file->write_text("hello\n"))
		return 3;

	auto text = file->read_text();
	if (!text || text->size() != 6U)
		return 4;
	auto found = root->rglob("*.txt");
	if (!found || found->size() != 1U || (*found)[0].name() != ca::sv::str{"notes.txt"})
		return 5;
	auto is_dir = deep->is_directory();
	if (!is_dir || !*is_dir)
		return 6;

	auto a = root->join("a");
	if (!file->unlink() || !deep->rmdir() || !a || !a->rmdir() || !root->rmdir())
		return 7;
	return text->cleanup() && found->cleanup() && file->cleanup() && deep->cleanup() && a->cleanup()
		&& root->cleanup() ? 0 : 8;
}
```

A path converts to `sv::str` (`view()`) and gives `c_str()` for system calls; it prints with `{}` and is hashable, by its text, so it can key a `hashmap` (looked up by another path). `glob` and `iterdir` return a `dynamic_array` of paths, whose `cleanup()` cleans every path in it.

## `fs/path.hpp`

Performance of ca::fs::basic_path\<A> (ca::fs::path: A = ca::heap).

Layout: a pointer to a NUL-terminated block from A and a size, 16 bytes on 64-bit, plus the allocator when stateful (24 with arena_allocator). "." owns no memory (null pointer), so default construction and moved-from paths cost nothing.

| Operation | Time | Allocation |
|---|---|---|
| view, c_str, is_absolute, root | O(1) | none |
| name, stem, suffix, parent | O(n) backward scan | none: views into the path |
| components | O(n) total, lazy | none |
| relative_to, is_relative_to, == | O(n) memcmp | none |
| match | O(n * m) worst case per component, no backtracking across components | none |
| make, join, push, with_name, with_stem, with_suffix, clone | O(n) single pass | one heap block |
| filesystem queries | one syscall | none |
| iterdir, glob | one syscall per entry | one heap block per result, plus the array |

Normalization happens once, when a path is built: repeated slashes and "." components drop out, so every accessor is a scan of an already-clean string, never a re-parse. ".." is kept (lexically resolving it would be wrong across symlinks), as in pathlib.

Locality: the bytes are contiguous and NUL-terminated, so system calls take c_str() with no copy. Views returned by the accessors point into that block and die with it.

Relocation and copy: trivially relocatable (TRIVIALLY_RELOCATABLE), so dynamic_array\<path> grows by remapping or in place. The copy constructor is deleted; clone() is the explicit, fallible copy. Moves take two words and the allocator.

Allocation: every path, array and buffer a path builds comes from its allocator, so an arena-backed path builds arena-backed paths. A normalized text shorter than the block asked for is trimmed through ca::reallocate, in place within a heap size class.

Baseline std::filesystem::path (libstdc++); ca over ca::heap; operations on 4 paths: bench/path.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| make, messy input, 1e6 | 0.094x | 0.13x | std: constructor + lexically_normal |
| make, clean input, 1e6 | 0.34x | 0.49x | std: constructor only, no normalization |
| join of a file name, 1e6 | 0.070x | 0.081x | std: operator/ |
| name + stem + suffix, 1e6 | 0.26x | 0.33x | |
| parent, 1e6 | 0.042x | 0.050x | |
| component iteration, 1e6 | 2.13x | 2.62x | libstdc++ splits components once, when constructing; ca scans on each walk |

## `io/`

I/O in memory: readers and writers over buffers and strings, a ring buffer stream, and the line and whole-input readers that work over any buffered reader, a file or a string alike.

| Type | Role |
|---|---|
| `io::memory_writer` | writes into fixed memory the caller provides: the snprintf of `format_to` |
| `io::string_writer<S>` | appends to a `ca::str` or `inline_str`, formatting in place in its spare capacity |
| `io::memory_reader` | a buffered reader over text it does not own: parse a string like a file |
| `io::ring_buffer<A>` | an in-memory byte stream (FIFO) over a power-of-two ring, for one thread |
| `io::spsc_ring_buffer<A>` | the same between two threads, one writing, one reading, lock-free |
| `io::read_line(reader, line)` | the next line, without its `'\n'`, into a string or char array |
| `io::read_to_end(reader, out)` | the rest of the input appended to a string or char array |

All writers here are windowed (`io::is_windowed_writer`): `format_to` writes straight into their memory. A message that does not fit is dropped whole, never cut, and the call fails with `errc::no_space` (or out of memory for a growable string), also kept sticky until `flush()`.

```c++
#include "ca/error.hpp"
#include "ca/format_to.hpp"
#include "ca/inline_str.hpp"
#include "ca/memory_writer.hpp"
#include "ca/str.hpp"
#include "ca/string_writer.hpp"

auto main(void) -> int {
	char buffer[16];
	ca::io::memory_writer m{buffer};
	if (!ca::format_to(m, "{}+{}", 2, 3) || m.view() != ca::sv::str{"2+3"})
		return 1;
	auto overflow = ca::format_to(m, "{:>20}", "x");
	if (overflow || overflow.error() != ca::errc::no_space || m.view() != ca::sv::str{"2+3"})
		return 2;
	m.clear();

	ca::str log{};
	ca::io::string_writer<ca::str> out{log};
	for (int i = 0; i < 3; ++i)
		if (!ca::format_to(out, "[{}]", i))
			return 3;
	if (!out.flush() || log != ca::sv::str{"[0][1][2]"})
		return 4;

	ca::inline_str<4> tag;
	ca::io::string_writer<ca::inline_str<4>> bounded{tag};
	auto too_long = ca::format_to(bounded, "{}", 123456);
	return !too_long && tag.empty() && log.cleanup() ? 0 : 5;
}
```

### Reading lines

`read_line` and `read_to_end` take any `io::is_buffered_reader`: a `memory_reader` here, an `io::reader` over a file or stdin in layer 6. Chunks are copied straight from the reader's buffer into the line, whatever its length. `read_line` drops the `'\n'` but keeps a `'\r'` before it (strip it with `strip_end()` for CRLF input), and returns false at the end of input when nothing was left. For a line that fits the reader's buffer, `reader.read_until('\n')` returns a view of it without any copy.

```c++
#include "ca/dynamic_array.hpp"
#include "ca/memory_reader.hpp"
#include "ca/read_line.hpp"
#include "ca/read_to_end.hpp"
#include "ca/str.hpp"

auto main(void) -> int {
	ca::io::memory_reader reader{"name=ada\nlang=c++\n\nrest of the file"};
	ca::str line{};
	int fields = 0;
	for (;;) {
		auto got = ca::io::read_line(reader, line);
		if (!got)
			return 1;
		if (!*got || line.empty())
			break;
		fields += line.partition("=").found() ? 1 : 0;
	}
	if (fields != 2)
		return 2;
	ca::dynamic_array<char> rest{};
	auto n = ca::io::read_to_end(reader, rest);
	if (!n || *n != 16U || !reader.at_end())
		return 3;
	return line.cleanup() && rest.cleanup() ? 0 : 4;
}
```

### Ring buffer

`ring_buffer<A>` is a stream (`io::is_stream`) over a ring of bytes from A, its capacity rounded up to a power of two (`make(capacity)`). Writes append, reads take from the front; it is also a buffered reader (`fill`, `consume`) and a windowed writer, so text can be formatted into it and parsed out of it in place. A write that does not fit is refused whole.

```c++
#include "ca/format_to.hpp"
#include "ca/ring_buffer.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto made = ca::io::ring_buffer<>::make(12U);
	if (!made || made->capacity() != 16U)
		return 1;
	ca::io::ring_buffer<>& ring = *made;
	if (!ring.write(ca::sv::str{"hello "}) || !ca::format_to(ring, "{}!", 42))
		return 2;
	char out[16];
	auto got = ring.read(out);
	if (!got || ca::sv::str{out, *got} != ca::sv::str{"hello 42!"} || !ring.empty())
		return 3;
	return ring.cleanup() ? 0 : 4;
}
```

## `io/ring_buffer.hpp`

In-memory byte stream over a fixed ring of bytes from an allocator.

Performance:

- Layout: buffer pointer, capacity, read and write counts, the message in progress, the sticky error and the allocator (0 bytes for a stateless one, 8 for arena_allocator); 48 bytes on 64-bit with ca::heap.
- Capacity is a power of two: positions are free-running counts masked into the ring, no modulo, no branch on wrap besides the split copy.
- read() and write() are one bounds check and at most two memcpy (one when the bytes do not cross the end of the ring). fill()/consume() and window()/drain()/settle() lend the ring itself: parsing and formatting work in place, no staging copy.
- Emptying the ring (read or consume reaching the write count) rewinds both counts to the start, so the next window and fill are as long as possible.
- Time: read, write, fill, consume, window, settle O(1) besides the bytes copied.
- Space: capacity bytes, one allocation from A made by the factory, 64-byte aligned (one cache line); never grows.
- Copy: none (move only, the moved-from ring is empty). Trivially relocatable in practice, not declared so.

Baseline std::deque\<char> as a FIFO; ca is a 4 KiB ring: bench/ring.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| 64 B write + read, 1e6 | 0.11x | 0.082x | |
| 1-256 B messages, 2 KiB in flight, 1e6 | 0.24x | 0.44x | gcc inlines the bounded copies as rep movsb |
| format "{} {}\n" into the ring, 1e6 | 0.50x | 0.42x | std: std::format_to through a back_inserter |

### class `ring_buffer`

```c++

```

## `io/spsc_ring_buffer.hpp`

Performance of ca::io::spsc_ring_buffer\<A>.

- Layout: the handle is a pointer to the shared block, the bytes, the capacity and the allocator (24 bytes with ca::heap). The block holds the consumer's line (its count and the last producer count it saw), the producer's line (its count, the last consumer count it saw, the message in progress, the sticky error), then the bytes, 64-byte aligned.
- Each side reads the other's count only when its cached copy is not enough for the call: a read wanting more than it knows is there, a write or window wanting more room. Publishing is one release store, a plain mov on x86: no locked instruction, no fence, on either side.
- read() and write() are one bounds check and at most two memcpy, as in ring_buffer. fill()/consume() and window()/drain()/settle() lend the ring itself, so parsing and formatting work in place across threads, without a staging copy. A message becomes visible to the consumer whole, at settle or at the end of write, never in part.
- Unlike ring_buffer, an empty ring is not rewound to its start (that would write the producer's count from the consumer's side): a window or fill can stop at the end of the ring and continue past the wrap.
- Time: read, write, fill, consume, window, settle O(1) besides the bytes copied.
- Space: two 128-byte lines and capacity bytes, one allocation from A made by the factory; never grows.
- Copy: none; the handle moves (the block stays where it is), but not while shared.

Baseline a std::deque\<char> behind a std::mutex; ca is a 4 KiB ring; one thread writing and reading in turn, so the figures are the cost of the operations themselves, without the cache-line transfers of two threads (the harness runs on one CPU):

## `list/`

Doubly linked lists, for when elements must not move: their addresses stay valid through insertions, removals, sorting and splicing, and both ends cost O(1).

| Type | Nodes | Fails |
|---|---|---|
| `list<T, A>` | one node per element, from A | on allocation (`append`, `insert`, `clone`) |
| `intrusive_list<T, Tag>` | the links live in the elements | never: it allocates nothing |

Both have `append`, `prepend`, `insert` before a position, `pop`, `pop_front`, `first`, `last`, `remove`, `reverse`, `splice` (moves all of another list in O(1)), and a stable merge `sort` that relinks nodes and never moves an element. `list` adds `find`, `count`, `contains`, `retain`, `extend`, `clone` and `cleanup`.

```c++
#include "ca/array.hpp"
#include "ca/list.hpp"
#include "ca/utility.hpp"

auto main(void) -> int {
	ca::list<int> l{};
	if (!l.extend({5, 3, 9}) || !l.prepend(1) || !l.append(7))
		return 1;
	const int* const three = &*l.find(3).value_or(l.end());
	l.sort();
	if (&*l.find(3).value_or(l.end()) != three)
		return 2;

	auto at = l.find(5);
	if (!at || !l.insert(*at, 4))
		return 3;
	if (!l.retain([](const int& v) noexcept { return v != 9; }))
		return 4;

	ca::list<int> tail{};
	if (!tail.extend({100, 200}))
		return 5;
	l.splice(l.end(), ca::move(tail));
	int expected[] = {1, 3, 4, 5, 7, 100, 200};
	ca::usz i = 0U;
	for (const int v : l)
		if (v != expected[i++])
			return 6;
	return i == 7U && tail.empty() && l.cleanup() ? 0 : 7;
}
```

### Intrusive lists

An element joins an `intrusive_list<T, Tag>` by deriving `ca::list_link<T, Tag>` once per list it can be in; the Tag tells the links apart, so one object can sit in several lists at once (a task in a run queue and in a timer list). The list stores nothing per element and allocates nothing, so no operation can fail. Misuse traps: linking an element that is already linked, or removing one that is not. Links and lists are trivially destructible, so a trap can unwind past them (see `ca::context_manager`): an element leaves its list before it is destroyed, and a list is cleared before it goes away, unchecked.

```c++
#include "ca/intrusive_list.hpp"
#include "ca/list_link.hpp"

struct by_priority;

struct task final : ca::list_link<task>, ca::list_link<task, by_priority> {
	int id;
	int priority;
	task(const int identifier, const int level) noexcept : id{identifier}, priority{level} {
	}
};

auto main(void) -> int {
	task a{1, 3};
	task b{2, 1};
	task c{3, 2};
	ca::intrusive_list<task> arrival;
	ca::intrusive_list<task, by_priority> urgent;
	arrival.append(a);
	arrival.append(b);
	arrival.append(c);
	for (task& t : arrival)
		urgent.append(t);
	urgent.sort([](const task& l, const task& r) noexcept { return l.priority < r.priority; });

	const bool ordered = urgent.first().value_or(a).id == 2 && arrival.first().value_or(c).id == 1;
	arrival.remove(b);
	const bool removed = arrival.size() == 2U && urgent.size() == 3U;
	arrival.clear();
	urgent.clear();
	return ordered && removed ? 0 : 1;
}
```

`list` has no sentinel node, so the list object itself holds no self-pointer and relocates with a memcpy; `end()` is a null node that remembers its list, so `--end()` still reaches the last element, and like every iterator it is invalidated when the list object moves.

## `list/intrusive_list.hpp`

Performance of ca::intrusive_list<T, Tag>.

Layout: first and last link pointers and the size, 24 bytes on 64-bit. The links live in the elements: each T derives from list_link<T, Tag>, two pointers, so the list allocates nothing and no operation can fail. Unlike ca::list, the elements are wherever their owner put them (an array, an arena, the stack, inside another object); the list only orders them.

| Operation | Time | Notes |
|---|---|---|
| append, prepend, insert(position) | O(1) | four pointer stores, one linked() check |
| remove(element), pop, pop_front | O(1) | no search: the element knows its neighbours |
| iterator_to(element) | O(1) | |
| splice(position, other) | O(1) | |
| first, last, size, empty, begin, end | O(1) | |
| reverse, clear | O(n) | clear unlinks every element |
| sort | O(n log n) | stable merge on the links, as ca::list |

Space: 16 bytes per element per list it can join (one list_link per Tag), nothing else.

Locality: as ca::list, a dependent load per element; when the elements sit in an array, a walk in array order touches memory in order.

Rules, checked: an element is in at most one list per Tag (linking a linked element traps); remove() takes elements of this list (removing an unlinked one traps). Unchecked, for trivial destructors (a trap unwinds past them, see ca::context_manager): an element leaves its list before it is destroyed, and a list is cleared before it goes away. Copying or moving an element gives an unlinked one; relocating a linked element by bytes would corrupt the list, so list_link is not trivially copyable.

Copy and move: the list is move-only; moving takes three words, the elements stay where they are. TRIVIALLY_RELOCATABLE: no element points at the list object.

| Operation | Time | Notes |
|---|---|---|
| append, prepend, emplace, emplace_front, insert(position) | O(1) | one allocation |
| pop, pop_front, pop(position) | O(1) | one deallocation |
| first, last, size, empty, begin, end | O(1) | |
| splice(position, other) | O(1) | no allocation, no element touched |
| extend(view) | O(n) | n allocations, linked once all succeed |
| find, count, contains, remove(value) | O(n) | pointer chasing |
| retain(test) | O(n) | |
| reverse | O(n) | swaps the links, elements stay in place |
| sort | O(n log n) | stable merge sort on the links: no allocation, elements never move |
| clear, cleanup, clone | O(n) | |

A list earns its place where elements must not move (pointers to them stay valid for their lifetime: no relocation ever), where splicing whole runs in O(1) matters, or where elements are inserted and removed in the middle through positions already held.

## `list/impl/`

`merge_sort_links.hpp`: the sort shared by `list` and `intrusive_list`. It works on the links only, merging as a binary counter: runs of 1, 2, 4, ... nodes wait in 64 slots and each node is merged while still in cache (the scheme of libstdc++'s `list::sort`), instead of log n sweeps over the whole list. `merge_link_chains` takes the left run first among equals, so the sort is stable, and the back links are rebuilt in one final pass. No element is moved, copied or compared more than O(n log n) times, no memory is allocated, and an element's address stays the same, so pointers into the list survive sorting. `link_run` holds the two ends of a chain while it is relinked.

## `map/`

Maps and sets with Python's dict and set API.

| Type | Structure | Order | Counterpart |
|---|---|---|---|
| `hashmap<K, V, A>` | Swiss table, open addressing | none | dict, `std::unordered_map` |
| `map<K, V, A>` | B-tree of order 12 | sorted by key | `std::map`, with floor and ceiling |
| `set<K, A>` | the Swiss table over keys | none | set |

Both maps satisfy `ca::is_map`, the dict contract as ca spells it:

| Python | ca |
|---|---|
| `d[k]` | `m[k]`: traps when k is absent |
| `d.get(k)` | `m.get(k)`: an `optional<V&>` |
| `d[k] = v` | `m.set(k, v)`: a `result`, since it may allocate |
| `k in d` | `m.contains(k)` |
| `d.setdefault(k, v)` | `m.setdefault(k, v)`: a pointer to the value, existing or new |
| `d.pop(k)`, `d.popitem()` | optionals |
| `d.keys()`, `d.values()`, `d.items()` | the same; iteration yields `item<const K&, V&>` |
| `{k: v for ... if ...}` in place | `m.retain(predicate)` |

```c++
#include "ca/hashmap.hpp"
#include "ca/str.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	ca::hashmap<ca::str, int> ages{};
	if (!ages.set("ada", 36) || !ages.set("alan", 41) || !ages.set("ada", 37))
		return 1;
	if (ages.size() != 2U || ages["ada"] != 37 || ages.get("grace"))
		return 2;

	auto count = ages.setdefault("grace", 0);
	if (!count)
		return 3;
	**count += 85;

	int total = 0;
	for (auto [name, age] : ages.items())
		total += name.starts_with("a") ? age : 0;
	if (total != 78 || ages["grace"] != 85)
		return 4;

	if (!ages.retain([](const ca::str& name, int&) noexcept { return name != ca::sv::str{"alan"}; }))
		return 5;
	auto gone = ages.pop("ada");
	if (!gone || *gone != 37 || ages.size() != 1U)
		return 6;
	return ages.cleanup() ? 0 : 7;
}
```

### Keys

Keys are looked up through `lookup_of<K>`: `K::view_type` when K has one, so a `hashmap<ca::str, V>` is searched with an `sv::str` (or a literal) and never builds a string to look one up. `set` and `setdefault` build the key only when it is absent, converting a literal or a view with `K::make` when needed. `ca::hash` hashes integers and enums by value, pointers, text by its code units (so a `str` hashes as its view) and any type with a `hash() const -> u64` member; `ca::is_hashable` lists them.

```c++
#include "ca/hash.hpp"
#include "ca/hashmap.hpp"
#include "ca/integers.hpp"
#include "ca/is_hashable.hpp"

struct cell final {
	int x;
	int y;
	[[nodiscard]] auto hash(void) const noexcept -> ca::u64 {
		return ca::hash_word(static_cast<ca::u64>(static_cast<ca::u32>(x)) << 32U | static_cast<ca::u32>(y));
	}
	[[nodiscard]] auto operator==(const cell&) const noexcept -> bool = default;
};

static_assert(ca::is_hashable<cell>);

auto main(void) -> int {
	ca::hashmap<cell, char> board{};
	if (!board.set(cell{0, 0}, 'x') || !board.set(cell{1, 2}, 'o'))
		return 1;
	return board[cell{1, 2}] == 'o' && !board.contains(cell{2, 1}) && board.cleanup() ? 0 : 2;
}
```

### Sorted maps and sets

`map` iterates in key order and adds `first`, `last`, `pop_first`, `floor(k)` (the greatest key not above k) and `ceiling(k)`. `set` has Python's set API: `add`, `discard`, `remove`, `pop`, the operations `union_with` (`union` is a keyword), `intersection`, `difference`, `symmetric_difference` and their `_update` forms, and `is_subset`, `is_superset`, `is_disjoint`.

```c++
#include "ca/array.hpp"
#include "ca/map.hpp"
#include "ca/set.hpp"

auto main(void) -> int {
	ca::map<int, const char*> grades{};
	if (!grades.set(90, "A") || !grades.set(80, "B") || !grades.set(70, "C"))
		return 1;
	auto grade = grades.floor(85);
	if (!grade || grade->key != 80 || grades.first().value_or(*grade).key != 70)
		return 2;

	auto a = ca::set<int>::make(ca::array{1, 2, 3, 4});
	auto b = ca::set<int>::make(ca::array{3, 4, 5});
	if (!a || !b)
		return 3;
	auto common = a->intersection(*b);
	if (!common || common->size() != 2U || !common->is_subset(*a) || !common->contains(3))
		return 4;
	return grades.cleanup() && a->cleanup() && b->cleanup() && common->cleanup() ? 0 : 5;
}
```

Values and keys that are cleanable are cleaned by the map's `cleanup()`; an `item` popped out owns its key and value and has its own `cleanup()`.

## `map/hashmap.hpp`

Performance of ca::hashmap<K, V, A>.

Layout: control pointer, slot pointer, mask, size and growth left, 40 bytes on 64-bit, plus the allocator (nothing for ca::heap). One block holds a control byte per slot, then the slots, each an item<K, V> (the key and the value side by side: one cache line serves the compare and the value). An empty hashmap owns no memory: it points at a shared group of EMPTY control bytes, so lookups take the same path with or without storage.

| Operation | Time | Notes |
|---|---|---|

A group is W control bytes matched at once: W = 16 on x86-64 (one SSE2 compare and pmovmskb), 8 elsewhere (a 64-bit word, SWAR).

| Operation | Time | Notes |
|---|---|---|
| get, contains, operator[] | O(1) expected | hash, one W-byte control load and match per group probed, one key compare per tag hit (1/128 false hits per slot) |
| set, setdefault | amortized O(1) expected | the lookup, then an insert into the first free slot met |
| pop(key) | O(1) expected | marks the slot EMPTY when its group has one, else DELETED |
| popitem | O(capacity / W) worst | scans control groups from the start |
| iteration, keys, values, items | O(capacity / W + size) | W control bytes per step |
| reserve, shrink, growth | O(capacity) | every slot rehashed and relocated (memcpy for trivially relocatable items) |
| clear, cleanup | O(capacity / W + size) | no walk for trivially destructible items without cleanup() |
| clone | O(capacity) | same placement, no rehash; one memcpy for trivially copyable items |
| update | O(other.size) | |

Space: capacity is a power of two from W, at most 7/8 of it used, so 1 + sizeof(item) bytes per slot at 44% to 87.5% load right after growth; a map of up to 14 items is one group on x86-64. Growth doubles, or rehashes in place when DELETED slots, not elements, filled the table.

Locality: a lookup touches one control group (W bytes) and, on a tag hit, one slot; misses rarely touch a slot. Probing walks aligned groups triangularly, so it visits every group. 16-byte groups replaced 8-byte SWAR ones on x86-64: lookups, walks, churn and small maps faster, most of all churn and small maps; insertion and str keys unchanged within noise. A group holds up to 14 items before a probe moves on, so fewer probes reach a second group and DELETED slots fill the table later.

Hashing: ca::hash, wyhash on bytes, one 128-bit multiply on integers. Keys are looked up by lookup_type: an sv for str keys, so literals and views never build a string.

Relocation: TRIVIALLY_RELOCATABLE when A is; slots relocate with memcpy on growth when the item is trivially relocatable (str keys included).

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy. Move takes five words and the allocator, no allocation.

Inlining: get and contains inline to the probe loop; growth and rehash are out of line and take the allocator by value, not the map.

Baseline std::unordered_map over glibc malloc; ca over ca::heap; u64 keys and values unless said: bench/hashmap.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| insert 1e6 scrambled u64, growing, then cleanup | 0.12x | 0.11x | |
| 1e7 lookup hits in 1e6 entries | 0.45x | 0.43x | |
| 1e7 lookup misses | 0.090x | 0.099x | misses rarely touch a slot |
| walk 1e6 entries 10 times | 0.14x | 0.14x | |
| insert + pop churn, 1e5 live, 5e6 rounds | 0.22x | 0.25x | DELETED reclaimed by in-place rehash |
| 1e5 maps of 8 ints, built, read, destroyed | 0.57x | 0.29x | |
| str keys, 1e5 inserted, 1e6 lookups by literal | 0.40x | 0.31x | std: std::string keys |

## `map/map.hpp`

Performance of ca::map<K, V, A>.

Layout: root pointer and size, 16 bytes on 64-bit, plus the allocator (nothing for ca::heap). A B-tree of order 12: each node holds up to 11 sorted keys in one array and their values in another, so a node search scans contiguous keys only; branches add 12 child pointers. Leaves are 16 bytes of header plus 12 keys and 12 values (one spare of each for the overflow before a split). An empty map owns no memory.

| Operation | Time | Notes |
|---|---|---|
| get, contains, operator[] | O(log n) | log12(n) to log6(n) nodes, a linear scan of up to 11 keys in each |
| set, setdefault | O(log n) | at most one node per level allocated, all before anything changes |
| pop, popitem, pop_first | O(log n) | rotations and merges, no allocation |
| first, last | O(log n) | one descent |
| floor, ceiling | O(log n) | |
| iteration, keys, values, items | O(n) | in key order; amortized O(1) per step |
| retain | O(n + r log n) | r entries removed |
| clear, cleanup, clone | O(n) | clone copies the tree shape, memcpy per node for trivially copyable entries |

Space: nodes are at least half full (5 of 11 keys) except the root; for small entries the overhead per entry is about 16 / 8 + 8 / 6 bytes: far below a red-black tree's three pointers and color per entry.

Locality: a lookup touches about log12(n) nodes, each scanned linearly in one or two cache lines of keys; a std::map node walk is a dependent load per level of log2(n).

Relocation: entries move inside and between nodes on insertion and removal (memmove for trivially relocatable keys and values); positions and references do not survive them. TRIVIALLY_RELOCATABLE when A is: nodes point at their parent, never at the map.

Copy and move: the copy constructor is deleted; clone() is the explicit, fallible copy. Move takes two words and the allocator.

Baseline std::map over glibc malloc; ca over ca::heap; u64 keys and values unless said: bench/map.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| insert 1e6 scrambled u64, then cleanup | 0.74x | 0.78x | entries shift within nodes |
| insert 1e6 u64 in order | 0.24x | 0.32x | |
| 3e6 lookup hits in 1e6 entries | 0.57x | 0.32x | |
| 1e6 ceiling misses | 0.52x | 0.67x | std: lower_bound |
| walk 1e6 entries 10 times | 0.14x | 0.15x | |
| insert 1e6, then pop all in scrambled order | 0.31x | 0.31x | |
| str keys, 1e5 inserted, 5e5 lookups by literal | 0.45x | 0.49x | std: std::less<> and string_view lookups |

## `map/impl/`

The two structures under the maps, and what they share.

### Swiss table (`hashmap`, `set`)

- `control_group.hpp`: the group of control bytes, one per slot, matched together: `vector_group.hpp` on x86-64 (16 bytes, one SSE2 compare and pmovmskb through `ca::simd`), `swar_group.hpp` elsewhere and in an integer-only build (8 bytes in a 64-bit word, portable, no vector unit needed). A full slot holds the low 7 bits of its key's hash; EMPTY and DELETED have the high bit set. `match(tag)` returns the slots whose tag is equal, so a lookup compares a key only on a tag hit, about 1 in 128 slots. Both give the same interface (`WIDTH`, `SHIFT`, `bits`, `first`, `from`), so the table is written once. `empty_control` is one shared group of EMPTY bytes that every table without storage points at, so lookups need no branch for the empty case.
- `hash_table.hpp`: the table itself, over slots of any type: one block holding the control bytes then the slots, power-of-two capacity, at most 7/8 full, triangular probing over aligned groups. `hashmap` stores `item<K, V>` in the slots, `set` stores K.

### B-tree (`map`)

`btree_node.hpp`: nodes of up to 12 sorted keys and their values in two separate arrays, so a scan inside a node touches keys only, plus the parent and the index in it; one spare slot lets an insertion overflow a full node before it splits. `btree_branch` adds the children: child i holds the keys between keys i - 1 and i. `btree_iterator` walks in key order through parent links, showing each entry through a projection (`item<const K&, V&>`, a key, or a value).

### Shared

- `key.hpp`: `lookup_of<K>`, the type keys are looked up by (`K::view_type` when K has one, else `const K&`); `key_order` (`compare()` when available, else `<`); `make_from`, which builds a key only when an insertion needs one, by constructor, `clone()` or `K::make`; `clean`, which runs a key's or value's `cleanup()` keeping the first error.
- `range.hpp`: a begin and an end for range-for, what `keys()`, `values()` and `items()` return.

## `regex/`

Regular expressions with Python's `re` syntax and API, matched in time linear in the text.

| Type | What it is | Python |
|---|---|---|
| `ca::regex` (`basic_regex<A>`) | a compiled pattern, in memory from A | `re.Pattern` |
| `ca::regex_pattern` | a pattern's text: checked when it compiles if literal | the pattern string |
| `ca::regex_flags` | `ignore_case`, `multiline`, `dot_all`, `verbose`, `ascii` | `re.I`, `re.M`, `re.S`, `re.X`, `re.A` |
| `ca::regex_match<A>` | one match: groups, positions, `expand` | `re.Match` |
| `regex_matches<R>` (`R::matches_type`) | the matches one by one, from `finditer` | the iterator of `finditer` |
| `ca::regex_error` | why a pattern does not compile, and where | `re.error` (`msg`, `pos`) |

`ca::regex::make(pattern, flags)` (or `compile`) acquires a regex: `result<regex>`, failing with `errc::invalid_argument` and the syntax error's message as the trace frame, or out of memory. A literal pattern is checked when the program compiles, like a format string: `make("a)b")` is a compile error naming `regex_has_unbalanced_paren`. Text known only at runtime goes in explicitly, `ca::regex_pattern{text}`, and `regex_pattern{text}.check(flags)` gives the error's kind and position without building anything (constexpr).

The methods are Python's: `search`, `match`, `fullmatch` (`result<optional<regex_match>>`, the result failing only out of memory), `finditer`, `findall`, `split`, `sub` (a template with `\1`, `\g<name>`, or a function of the match), `escape`, `group_count`, `group_index`. A match borrows the text and the regex's group names; `m[1]` traps on a group the pattern does not have and is empty for one that took no part, `m.group(1)`, `m.start(1)`, `m.end(1)` give nothing then. Positions count code units (bytes of UTF-8), as everywhere in ca; `search(text, pos)` starts at pos while `^` and `\b` still see what precedes it, and a prefix of the text plays Python's endpos.

```c++
#include "ca/regex.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto date = ca::regex::make("(?P<year>\\d{4})-(?P<month>\\d\\d)");
	if (!date)
		return 1;
	auto found = date->search("paid 2026-11, due 2026-12");
	if (!found || !*found)
		return 2;
	ca::regex_match<>& m = **found;
	if (m.group() != ca::sv::str{"2026-11"} || m["month"] != ca::sv::str{"11"} || m.start() != 5U)
		return 3;
	auto swapped = date->sub("\\g<month>/\\g<year>", "2026-11 and 2026-12");
	if (!swapped || *swapped != ca::sv::str{"11/2026 and 12/2026"})
		return 4;
	auto words = ca::regex::make("\\W+");
	if (!words)
		return 5;
	auto pieces = words->split("one, two;three");
	if (!pieces || pieces->size() != 3U || (*pieces)[2U] != ca::sv::str{"three"})
		return 6;
	return m.cleanup() && swapped->cleanup() && pieces->cleanup() && words->cleanup() && date->cleanup() ? 0 : 7;
}
```

### Syntax

Python's, over UTF-8: literals and escapes (`\n \t \xhh \uhhhh \Uhhhhhhhh`, octal `\0` and `\ooo`), `.`, classes `[a-z]`, `[^...]` with `\d \w \s` and their negations inside, anchors `^ $ \A \Z \b \B`, groups `(...)`, `(?:...)`, `(?P<name>...)`, comments `(?#...)`, alternation, the greedy and lazy repeats `* + ? {n} {n,} {,m} {n,m}`, inline flags `(?imsxa)` at the start and `(?i:...)`, `(?-i:...)` for a group. Unknown escapes of ASCII letters are errors, as in Python.

`\w \d \s` are Unicode's (Python's `str.isalnum` or `_`, `str.isdecimal`, `str.isspace`), ASCII under `ascii`; `ignore_case` takes characters as Python's re does (same simple lowercase, plus re's extra pairs: `k`, `K` and the Kelvin sign; `s`, `S` and `ſ`; ...). The classes and the caseless pairs are tables generated from the running Python and checked against its re for every code point (`make unicode`). `\B` matches an empty text, as in Python 3.14 (not 3.12).

### What a linear-time engine leaves out

Backreferences (`\1` in a pattern, `(?P=name)`), lookahead and lookbehind, conditionals `(?(1)...)`, atomic groups and possessive repeats, `\N{name}`: each is an error of its own kind (`regex_error::kind::backreference`, ...), at compile time for a literal. In exchange no pattern backtracks: matching costs O(text size * program size) whatever the input, with memory fixed when the regex is made. Patterns are bounded (groups nested 128 deep, repeats up to 100000, a program of 2^18 instructions and transitions), so a regex cannot take unbounded memory either.

### Matching

The pattern compiles to a Thompson NFA over UTF-8 bytes (a character class becomes a trie of byte ranges), run as a Pike VM: every possible thread advances one byte at a time, in priority order, so the first thread to match is the match Python's backtracker would find (leftmost-first, greedy and lazy repeats as written), groups included. A loop whose body can match empty iterates as Python's does: past its minimum, an iteration that matched empty ends it, keeping its groups. Before running, the matcher skips the text to where a match can begin: the literal every match starts with (a substring search), else the bytes a match can start with. A pattern that is only a literal never runs the VM.

The scratch memory of the VM is taken by `make`, so matching allocates only what it returns (a match's groups when the pattern has groups, the lists of findall and split, sub's string). The matching methods therefore change the regex: one thread uses it at a time, `clone()` makes one for another thread. Text that is not valid UTF-8 can be searched: invalid bytes match no character, `.` and negated classes included.

```c++
#include "ca/regex.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto vowels = ca::regex::make("[aeiouy]+", ca::regex_flags::ignore_case);
	if (!vowels)
		return 1;
	auto all = vowels->findall("SEA Breeze");
	if (!all || all->size() != 3U || (*all)[0U] != ca::sv::str{"EA"})
		return 2;
	auto matches = vowels->finditer("Kepler");
	ca::usz count = 0U;
	while (true) {
		auto next = matches.next();
		if (!next)
			return 3;
		if (!*next)
			break;
		++count;
		if (!(*next)->cleanup())
			return 4;
	}
	const ca::optional<ca::regex_error> problem = ca::regex_pattern{ca::sv::str{"(a)\\1"}}.check();
	if (count != 2U || !problem || problem->what() != ca::regex_error::kind::backreference)
		return 5;
	return all->cleanup() && vowels->cleanup() ? 0 : 6;
}
```

## `regex/basic_regex.hpp`

Performance of ca::basic_regex\<A>.

Layout: the program (instructions of 16 bytes, byte-range transitions of 8, a guard word per instruction), the group names, the pattern, the prefix literal, and one scratch block for the matcher, all from A. Scratch per thread key: two sparse-set entries and two lists of slot words (2 per group, group 0 included, plus one per loop that can iterate empty); keys are the instructions, twice that when such a loop exists. The program is bounded by 2^18 instructions and transitions, so a regex takes at most a few MiB.

| Operation | Time | Notes |
|---|---|---|
| make | O(pattern + program) | parse, tree, NFA, analyses, one scratch allocation |
| search, match, fullmatch | O(text * program) worst case | each byte read once; threads deduplicated per position |
| literal-only pattern | O(text) | one substring search, the VM never runs |
| skip to a match start | O(text) | the literal every match starts with (substring search), else a 256-bit first-byte set |
| a match's groups | O(groups) | one allocation from A when the pattern has groups, none otherwise |
| findall, split, sub | O(text * program) | the scratch reused; only the result allocates |
| clone | as make | the pattern is compiled again |

No pattern backtracks: (a|b|c)*d, (a*)*b and their kin take linear time where a backtracker takes quadratic or exponential time. The price is a constant per text byte: every live thread advances one byte in turn, binary-searching its transitions past 8, so a match covering most of the text (\w+ over prose) costs more per byte than a backtracker that runs straight through it. A lazy DFA for match bounds, with the VM kept for groups, would remove that cost.

Locality: instructions and transitions are contiguous arrays walked by index; the thread lists are dense arrays in priority order with per-key slot rows, cleared in O(1).

Copy and move: the copy constructor is deleted, clone() recompiles; moves take the pointers, noexcept. Matching methods are not const (they use the scratch): one thread per regex.

Baseline std::regex (ECMAScript, libstdc++'s backtracker): bench/regex.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| compile ([a-z]+)@([a-z]+)\.com, 1e4 | 0.028x | 0.028x | ca: parse, tree, NFA, analysis, scratch; std: its NFA |
| missing 16-char literal in 256 KiB, 4 times | 0.007x | 0.007x | ca: no VM, one substring search |
| \w+ over 256 KiB, every match | 1.24x | 1.30x | slower: the VM steps every byte of each long match, std runs straight through |
| [a-z]+ing\b over 256 KiB, every match | 0.90x | 0.92x | ca: one pass per match attempt, no backtracking |
| ([a-z]+)@([a-z]+)\.com over 256 KiB, groups | 0.90x | 1.04x | ca: captures in the VM threads |
| a repeated 3-way alternation then d, 4 KiB without d, 20 times | 0.000x | 0.000x | std backtracks from every position: quadratic; ca: linear |
| sub(\s+, _) of 256 KiB | 0.41x | 0.44x | |
| split(,) of 256 KiB | 0.063x | 0.067x | ca: literal pattern, no VM |

## `regex/impl/`

The regex engine, in the order a pattern goes through it.

### Parsing

- `regex_parser.hpp`: Python's grammar, one pass over the UTF-8 pattern with a fixed stack of open groups (no recursion, no allocation), so the same code checks a literal in a consteval constructor and builds the tree at runtime. What it recognises goes to a sink.
- `regex_validator.hpp`: the sink that builds nothing, for `regex_pattern::check`.
- `regex_tree.hpp`: the sink that builds the tree (`regex_node.hpp`: nodes linked by index), with every character set resolved there to sorted code point ranges.
- `regex_ranges.hpp`: that set algebra: sorting and merging ranges, complements within the scalar values, the named classes (`\w \d \s`, Unicode from `2-vocabulary/unicode/impl/class_ranges.hpp` or ASCII), and the caseless closure of `ignore_case` from the caseless cycles of the same generated header.
- `regex_errors.hpp`: one undefined function per syntax error, called by the consteval check.

### Compiling

- `regex_compiler.hpp`: the tree to a Thompson NFA (`regex_program.hpp`: `regex_inst`, transitions of byte ranges), each node compiled knowing its successor. Counted repeats are unrolled; a set becomes a trie of the UTF-8 sequences of its ranges (`utf8_sequences.hpp` splits a range into byte range sequences), built as the sorted sequences stream in, identical states shared. A loop whose body can match empty gets a hidden slot holding where its iteration began and a `progress` instruction at the end of the body: leave when nothing was consumed, as Python's re.
- `regex_analysis.hpp`: what the matcher can skip by: the bytes a match can start with, whether it is anchored at the text's start, the literal every match starts with.

### Matching

`pike_vm.hpp` / `.cpp`: the Pike VM. Two thread lists (sparse sets: O(1) clear, insertion order is priority), the epsilon closure walked with an explicit stack that also restores capture slots, one byte of text per step. Every thread is told apart by its instruction and, inside a loop that can iterate empty, by whether its iteration is still empty (`guards`): two threads differing in that would end differently, so neither may stand for the other. All memory comes from one scratch block the regex takes when made. `regex_names.hpp` looks group names up; `regex_replacement.hpp` walks sub's templates, checking them before any text is produced.

## `string/`

Owned strings with Python's str API.

| Type | Storage | Units |
|---|---|---|
| `ca::str` | short text inline, longer from `ca::heap` | char, UTF-8 by convention |
| `ca::u8str`, `u16str`, `u32str`, `wstr` | the same | char8_t, char16_t, char32_t, wchar_t |
| `basic_str<C, A>` | the same, any allocator | any code unit |
| `inline_str<N, C>` | inline, at most N units, never allocates | any code unit |

A `str` is 24 bytes (three words) and holds up to 23 chars inline (11 UTF-16 units, 5 UTF-32), so most short strings never allocate. It is always NUL-terminated, so `c_str()` costs nothing. `inline_str<N>` has the same API over fixed storage, is constexpr and trivially copyable, and fails with `errc::no_space` where a `str` would grow.

Every string converts to its view (`sv::str` for `str`), and has every read-only method of the views: `strip`, `split`, `find`, `partition`, `starts_with`, `is_alpha`, ... The methods that produce new text return a new string in a `result`: `upper`, `lower`, `title`, `capitalize`, `swap_case`, `case_fold`, `replace`, `center`, `justify_left`, `justify_right`, `zero_fill`, `expand_tabs`, `repeat`. The modifying ones work in place: `append`, `push`, `insert`, `remove`, `assign`, `resize`, `pop`, `clear`, `append_code_point`.

```c++
#include "ca/str.hpp"
#include "ca/sv.hpp"
#include "ca/u16str.hpp"

auto main(void) -> int {
	auto s = ca::str::make("  Hello, World  ");
	if (!s)
		return 1;
	ca::str& text = *s;
	if (text.strip() != ca::sv::str{"Hello, World"} || !text.contains("World"))
		return 2;

	auto shout = text.upper();
	auto swapped = text.replace("World", "ca");
	auto boxed = ca::str::make("ok");
	if (!shout || *shout != ca::sv::str{"  HELLO, WORLD  "})
		return 3;
	if (!swapped || swapped->strip() != ca::sv::str{"Hello, ca"})
		return 4;
	if (!boxed)
		return 5;
	auto centered = boxed->center(6U, U'*');
	if (!centered || *centered != ca::sv::str{"**ok**"})
		return 6;

	if (!text.assign(text.strip()) || !text.append("!") || !text.insert(0U, ">> "))
		return 7;
	if (text != ca::sv::str{">> Hello, World!"} || text.c_str()[text.size()] != '\0')
		return 8;

	auto wide = ca::u16str::make(ca::sv::str{"café"});
	if (!wide || wide->size() != 4U || (*wide)[3] != u'é')
		return 9;
	return text.cleanup() && shout->cleanup() && swapped->cleanup() && boxed->cleanup() && centered->cleanup()
		&& wide->cleanup() ? 0 : 10;
}
```

`make` builds a string from a view of the same unit type, or transcodes from another encoding (`u16str::make(sv::str{...})`), invalid sequences becoming U+FFFD. Case mappings are the full Unicode ones, so `upper()` of "straße" is "STRASSE", and `case_fold()` is the right key for caseless comparison.

### join and collect

`ca::join(separator, items)` is Python's `sep.join(items)`: items is any range of things that convert to a view (views, strings, C strings, the pieces of a split), measured first so the result is allocated once at its exact size. `ca::collect` (in `array/`) gathers a range into a `dynamic_array`.

```c++
#include "ca/collect.hpp"
#include "ca/inline_str.hpp"
#include "ca/join.hpp"
#include "ca/sv.hpp"

constexpr auto tag(void) noexcept -> ca::inline_str<8> {
	ca::inline_str<8> t;
	static_cast<void>(t.append("v"));
	static_cast<void>(t.push('2'));
	return t;
}

static_assert(tag() == ca::sv::str{"v2"});

auto main(void) -> int {
	const char* const names[] = {"ann", "bob", "cy"};
	auto joined = ca::join(", ", names);
	if (!joined || *joined != ca::sv::str{"ann, bob, cy"})
		return 1;
	auto fields = ca::collect(ca::sv::str{"a,b,,c"}.split(","));
	if (!fields || fields->size() != 4U)
		return 2;
	auto back = ca::join(ca::sv::str{"-"}, *fields);
	if (!back || *back != ca::sv::str{"a-b--c"})
		return 3;
	return joined->cleanup() && fields->cleanup() && back->cleanup() ? 0 : 4;
}
```

## `string/basic_str.hpp`

Performance of ca::basic_str<C, A>.

Layout: 24 bytes on 64-bit plus the allocator (nothing for a stateless one). A union holds either the text itself (small string: up to INLINE_CAPACITY units, 23 chars, 11 char16_t, 5 char32_t) or a pointer, a size and a capacity. The last unit of the object tells them apart: inline, it holds INLINE_CAPACITY - size, which is 0 (the NUL) when full; allocated, it is the top of the capacity word, whose highest bit is set. Little-endian targets only.

| Operation | Time | Notes |
|---|---|---|
| size, capacity, data, view, c_str, operator[] | O(1) | one test of the tag unit |
| push | amortized O(1) | inline until INLINE_CAPACITY, then capacity doubles |
| append, assign | amortized O(n) | one memcpy; on growth one more of the old text |
| insert(i, text), remove(i, n) | O(size - i) | one memmove |
| reserve, shrink | O(n) | a new block, then one memcpy |
| clone | O(n) | no allocation when the text fits inline |
| find, count, strip, split, partition, is_* | O(n) | views, no allocation; split is lazy |
| upper, lower, title, ... | O(n) | one block of size() units; ASCII stored directly, other code points through the tables |
| replace | O(n) | a counting pass, then one block of the exact size |
| center, justify_*, zero_fill, repeat | O(n) | one block of the exact size |

Always NUL-terminated: c_str() is data(), the allocation holds capacity + 1 units.

Growth allocates the new block, copies, then frees the old one: appending or inserting a view of the string itself is safe, and a failed growth changes nothing. Capacity is what the allocator returns (the heap rounds to its size class).

Copy and move: the copy constructor is deleted; clone() is the fallible copy. Moving copies the 24 bytes and the allocator and leaves the source empty. Relocatable with memcpy (no pointer into itself), so dynamic_array<basic_str> grows with realloc.

Inlining: push, the fitting append, size, data and operator[] are inline; growth runs in out-of-line static helpers given pointers and sizes.

Baseline std::string (libstdc++, glibc malloc); ca over ca::heap: bench/string.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |
|---|---|---|---|
| make() of 10 chars, 1e6 | 1.00x | 1.01x | inline in both; built inside the result: returning it copies nothing |
| make() of 22 chars, 1e6 | 0.049x | 0.081x | std::string allocates past 15 |
| push 1e7 chars | 1.04x | 0.89x | |
| append 1e6 6-char words | 1.20x | 0.92x | |
| ca::format vs std::format, short result, 1e6 | 0.63x | 0.54x | |
| dynamic_array\<str> vs vector\<string>, 1e6 pushes, half inline | 0.78x | 0.87x | |
| view().find of a missing 16-char needle in 1 MiB, 20 times | 0.99x | 1.02x | |

Python methods, against the equivalent hand-written std loops: bench/string.cpp on Intel Core i7-10750H, -O2, min of 9 runs: user cycles relative to the baseline.

| Case | clang 18 | gcc 13 | Notes |

## `trace/`

`ca::report<A>`: an error with its trace, owned, with formatted messages. The thread trace of layer 3 is free but limited: literal messages only, and it belongs to the thread, so the next failure replaces it. A report copies it into memory of its own, so it survives being stored, returned through many layers, or handed to another thread, and its frames can carry formatted text such as the path that failed.

A function returns `ca::result<T, ca::report<>>` instead of `ca::result<T>`, and adds frames with `ca::context(error, "reading {}", path)`: from a plain `ca::error` it starts a report with a copy of the thread trace, from a report it extends it, and in both cases the message is checked at compile time like any format.

```c++
#include "ca/context.hpp"
#include "ca/error.hpp"
#include "ca/format.hpp"
#include "ca/report.hpp"
#include "ca/result.hpp"
#include "ca/sv.hpp"
#include "ca/trace.hpp"
#include "ca/utility.hpp"

[[nodiscard]] static auto open(const ca::sv::str path) noexcept -> ca::result<int> {
	if (path.starts_with("/etc/"))
		return ca::trace::fail(ca::errc::access_denied, "open");
	return 4;
}

[[nodiscard]] static auto read_config(const ca::sv::str path) noexcept -> ca::result<int, ca::report<>> {
	auto file = open(path);
	if (!file)
		return ca::context(file.error(), "reading {}", path);
	return *file;
}

[[nodiscard]] static auto load(const int attempt) noexcept -> ca::result<int, ca::report<>> {
	auto config = read_config("/etc/app.conf");
	if (!config)
		return ca::context(ca::move(config).error(), "loading settings, attempt {}", attempt);
	return *config;
}

auto main(void) -> int {
	auto r = load(2);
	if (r)
		return 1;
	ca::report<>& report = r.error();
	if (report.error() != ca::errc::access_denied || report.size() != 3U)
		return 2;
	if (report.frame(1).message() != ca::sv::str{"reading /etc/app.conf"})
		return 3;
	auto text = ca::format("{}", report);
	if (!text || !text->view().starts_with("Permission denied\n  at open ("))
		return 4;
	return text->cleanup() && report.cleanup() ? 0 : 5;
}
```

Printed with `{}` or `ca::print_trace`, a report reads like a thread trace:

```text
Permission denied
  at open (config.cpp:12): open
  at read_config (config.cpp:19): reading /etc/app.conf
  at load (config.cpp:26): loading settings, attempt 2
```

A report holds the error, one string with every message end to end, and an array of frames (offset, size and source location): two allocations whatever the number of frames, none while the messages fit inline. All of it is paid on the failure path only. Frames that cannot be stored for lack of memory are counted in `dropped()` rather than failing the error path itself.

`ca::report<>::of(error)` builds one by hand, and `report.context("...", args...)` adds a frame in place. A context can fail with a report (`ca::with<ca::report<>>(enter, leave)`), which turns a trap into a report carrying the trap's reason. Clean a report up with `cleanup()`.

## `trace/context.hpp`

### function `context`

```c++
template <typename... Args>
requires (ca::is_displayable<Args> && ...)
[[nodiscard, gnu::cold]] auto context(const ca::error error, const ca::located_format_string<ca::type_identity<Args>...> format, const Args&... args) noexcept -> ca::failure<ca::report<>>;
```

Adds a formatted frame here (the caller) and returns the report to return, as E of a result<T, ca::report\<A>>. From an error, the report starts with a copy of its thread trace: `if (!f) return ca::context(f.error(), "opening {}", path);`. From a report, it grows it: `return ca::context(ca::move(r).error(), "loading {}", name);`.

## `trace/report.hpp`

ca::report: an error and its trace, owned.

- Layout: the error, a dropped count, one basic_str<char, A> holding every message end to end, and a dynamic_array\<A> of frames (offset and size in the text, source location): two allocations whatever the number of frames, none when the messages fit the string's inline capacity and no frame was added.
- Cost: failure path only. of() copies the thread trace's messages (one append each); context() formats in place at the end of the text, then pushes one frame. Both amortized O(message size).
- Never fails: a frame that does not fit in memory is counted in dropped() instead.
- frame(i) views the text: valid until the next context().

### class `report`
