# 3-system

_Generated by `tooling/autodoc.py` from `/* @DOC */` comments. Do not edit._

Layer 3: the boundary with the operating system. Everything ca needs from the kernel and the C library passes through here, and only here.

- `ca::sys`: one thin wrapper per POSIX call (files, directories, processes, signals, pipes, UDP sockets, memory mappings, time, environment, machine information), each returning a `ca::result` instead of -1 and errno.
- `ca::syscall`: the raw kernel entry points, from a table generated on the build machine, which `ca::sys` uses instead of libc wherever a table exists.
- `ca::errc`: the errno codes as `ca::error` constants, with their names and messages.
- `ca::trace`: the per-thread error trace, so an error can say where it came from.
- `ca::fs` options: the open flags as compile-time options (see `option_set`, layer 2).
- text: float formatting, the one piece of formatting that needs the C library.

### Nothing of libc leaks

No header of ca includes a system header, even a freestanding one. The wrappers are declared with ca types (`int` descriptors, `ca::span` buffers, `const char*` paths, `ca::sv::str` for text coming back) and defined in `.cpp` files, which alone include `<unistd.h>`, `<fcntl.h>` and the rest. System constants a header needs at compile time (open flags, errno values, signal numbers, struct layouts) are written per platform in the header and checked with `static_assert` against the real system header in the sibling `.cpp`, so a mismatch breaks the library build rather than a program. `make leaks` checks both rules.

### Errors

Every fallible wrapper returns `ca::result<T>`; the error is a `ca::errc` constant. ca keeps its own errno (`sys::last_error()`), written by the syscall table and by libc fallbacks, so a successful call in between never clobbers it. Calls that can be interrupted (`read`, `write`, `open`, ...) retry on EINTR themselves; `close` treats EINTR as success, since the descriptor is gone either way.

```c++
#include "ca/error.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto missing = ca::sys::open("/nonexistent/file", ca::fs::access::READ_ONLY, 0U);
	if (missing || missing.error() != ca::errc::no_entry)
		return 1;
	if (ca::sys::error_name(missing.error()) != ca::sv::str{"no_entry"})
		return 2;
	if (ca::sys::error_message(missing.error()) != ca::sv::str{"No such file or directory"})
		return 3;
	return ca::sys::last_error() == ca::errc::no_entry ? 0 : 4;
}
```

The wrappers are deliberately thin: they own nothing, so a descriptor from `sys::open` must be closed with `sys::close`. The owning types built on them are in layer 6: `fs::descriptor`, `io::writer`, `io::reader`.

## `elf/`

The ELF64 format, in `ca::elf`: the structures and constants of `<elf.h>` without including it, and two views that read them safely. Everything in ca that reads ELF goes through here: the vDSO lookup (`syscall::vdso_symbol`), the runtime's self-relocation and TLS setup, the executable range of a backtrace, and the symbolizer's sections. It is also the base of the dynamic loader.

The structures have the layout of their `<elf.h>` counterparts, checked field by field when the library builds (`layout.cpp`), so they overlay mapped memory and file bytes directly:

| ca::elf | elf.h | Constants |
|---|---|---|
| `file_header` | `Elf64_Ehdr` | `identity`, `file_types`, `machines` |
| `program_header` | `Elf64_Phdr` | `segment_types`, `segment_flags` |
| `section_header` | `Elf64_Shdr` | `section_types`, `section_flags`, `section_indices` |
| `symbol` | `Elf64_Sym` | `symbol_types`, `symbol_bindings`, `symbol_visibilities` |
| `dynamic_entry` | `Elf64_Dyn` | `dynamic_tags`, `dynamic_flags`, `dynamic_flags_1` |
| `relocation` | `Elf64_Rela` | `x86_64_relocations` |
| `auxiliary_entry` | `Elf64_auxv_t` | `auxiliary_types` |

Fields keep the ELF order with descriptive names (`_segments_offset` is `e_phoff`, `_address` is `p_vaddr`); the packed fields have accessors (`symbol::type()`, `relocation::symbol()`). Only ELF64 little-endian is read; ELF32 and big-endian files are refused.

Two views, owning nothing:

- `elf::file` reads a file as it lies on disk (usually a read-only mapping of it). `from` checks the header and that the program and section header tables fit inside the bytes, aligned; then `sections()`, `name(section)`, `find(".symtab")`, `linked(section)`, `contents(section)`, `string(table, offset)` and `symbols(table)` all stay inside the bytes, so a malformed or truncated file gives empty results instead of a fault.
- `elf::image` reads an object mapped for execution: the vDSO, the running program, or a library a loader mapped. `at(header)` takes a mapped file header, `of(segments, bias)` program headers whose bias is known (`bias_of` gives it from the program-headers segment), and `program()` is the running program. It reads the dynamic section once: `string`, `symbols`, `value(tag)`, the three relocation tables, and `find(name)`, a lookup through the GNU hash table (bloom filter first) or else the SysV one.

`image::program()` takes the program headers from the auxiliary vector and the bias from their PT_PHDR segment. A static PIE (how freestanding ca programs are linked with `-static-pie`) has none; its ELF header then sits right before its program headers, in the load segment at file offset 0, so `program()` reads that header through the kernel (`process_vm_readv`, which fails rather than faults), checks it is ELF64 with its program headers right after it, and takes the bias from that segment. It works the same under libc, in a static program and in a static PIE. The program's dynamic section is there only when it has one: a static non-PIE program has none, even linked with `--export-dynamic`, and its image has empty `dynamic()` and `symbols()`. Only what the program exports (`--export-dynamic`, or what the shared libraries it links reference) is in its dynamic symbol table. `ca::trace` takes the executable's range from it, and `ca::dl` binds plugins to what the program exports.

`elf::hashed_name::of(name)` computes both ELF hashes of a symbol name once, at compile time when the name is a constant, so a lookup through several images hashes the name only once.

The dynamic section's addresses are link-time addresses in the file, but libc's loader rewrites them in place to where they were mapped, in the objects it loads (the program included). An `image` takes an address inside the range the load segments were linked at as link-time and adds the bias, takes one inside the range they are mapped at as already rebased, and treats any other as absent. The vDSO, a static program and anything ca maps keep link-time addresses.

```c++
#include "ca/elf.hpp"
#include "ca/syscall.hpp"

auto main(void) -> int {
	const ca::u64 base = ca::syscall::auxiliary(ca::elf::auxiliary_types::vdso).value_or(0U);
	if (base == 0U)
		return 0;
	const auto vdso = ca::elf::image::at(*reinterpret_cast<const ca::elf::file_header*>(base));
	if (!vdso)
		return 1;
	constexpr auto name = ca::elf::hashed_name::of("__vdso_clock_gettime");
	const auto symbol = vdso->find(name);
	if (!symbol || symbol->type() != ca::elf::symbol_types::function)
		return 2;
	using clock_gettime = int (*)(int, void*);
	const auto call = reinterpret_cast<clock_gettime>(vdso->address(symbol->_value));
	long time[2] = {};
	return call(1, time) == 0 && time[0] > 0 ? 0 : 3;
}
```

## `environment/`

The process environment: read, set and remove variables, or take the whole block for `execve` and `posix_spawn`.

| Function | Does |
|---|---|
| `sys::getenv(name)` | the value as an `sv::str`, or nothing when unset |
| `sys::setenv(name, value, overwrite)` | sets name; an existing value is kept unless overwrite |
| `sys::unsetenv(name)` | removes name; removing a missing one succeeds |
| `sys::environ()` | the null-terminated array of "NAME=value" strings |

```c++
#include "ca/environment.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	if (!ca::sys::setenv("APP_MODE", "fast", true) || !ca::sys::setenv("APP_MODE", "slow", false))
		return 1;
	const ca::sv::str mode = ca::sys::getenv("APP_MODE").value_or(ca::sv::str{"default"});
	if (mode != ca::sv::str{"fast"})
		return 2;

	bool listed = false;
	for (char* const* entry = ca::sys::environ(); *entry != nullptr; ++entry)
		listed = listed || ca::sv::str{*entry}.starts_with("APP_MODE=");
	if (!listed)
		return 3;

	if (!ca::sys::unsetenv("APP_MODE"))
		return 4;
	return ca::sys::getenv("APP_MODE") ? 5 : 0;
}
```

The view `getenv` returns points into the environment block and stays valid only until the environment changes; copy it into a `ca::str` to keep it. `setenv` and `unsetenv` are not safe against a concurrent `getenv` in another thread, as in C: set the environment before starting threads.

## `error/`

System error codes and where they come from.

`ca::errc` names the errno values ca uses as `ca::error` constants, written per platform in `errc.hpp` and checked against `<errno.h>` when the library builds, so no program needs the header: `errc::no_entry` (ENOENT), `errc::access_denied` (EACCES), `errc::exists`, `errc::invalid_argument`, `errc::no_space`, `errc::out_of_range` (ERANGE), `errc::out_of_domain` (EDOM), `errc::try_again`, `errc::interrupted`, `errc::not_supported`, `errc::not_recoverable` (what a trapped context fails with), and the rest of the common set.

| Function | Answers |
|---|---|
| `sys::error_name(e)` | the errc constant's name, `"no_entry"`; empty for a code with none |
| `sys::error_message(e)` | the system's text, `"No such file or directory"`, untranslated |
| `sys::last_error()` | the calling thread's last system error |

Both strings have static storage. `error_message` never fails: an unknown code gives `"Unknown error"`.

```c++
#include "ca/error.hpp"
#include "ca/file.hpp"
#include "ca/sv.hpp"

[[nodiscard]] static auto describe(const ca::error e) noexcept -> ca::sv::str {
	if (e == ca::errc::no_entry)
		return "missing";
	if (e == ca::errc::access_denied || e == ca::errc::not_permitted)
		return "forbidden";
	return ca::sys::error_message(e);
}

auto main(void) -> int {
	if (describe(ca::errc::no_entry) != ca::sv::str{"missing"})
		return 1;
	if (ca::sys::error_name(ca::errc::exists) != ca::sv::str{"exists"})
		return 2;
	auto gone = ca::sys::rmdir("/definitely/not/here");
	return !gone && ca::sys::last_error() == gone.error() ? 0 : 3;
}
```

### ca owns errno

`sys::last_error()` is ca's own thread-local errno, not libc's: every failing `ca::syscall` call stores its code there (one store relative to `%fs`, no call), and the few paths that still go through libc copy libc's errno into it (`impl::libc_error`, kept in its own object so that programs without those paths never link errno). Since only failures write it, a successful call never clobbers the error a caller is about to inspect. `sys::set_last_error(e)` sets it by hand.

## `file/`

Files and directories through their POSIX calls, one wrapper per call, each returning a `ca::result`. Paths are NUL-terminated `const char*`; descriptors are plain `int`s the caller closes; buffers are spans, so a `char` array or any contiguous container passes directly.

| Group | Functions |
|---|---|
| open and close | `open`, `openat`, `close`, `dup`, `mkstemp`, `fcntl` |
| data | `read`, `write`, `write_all`, `pread`, `pwrite`, `seek`, `truncate`, `ftruncate`, `fallocate`, `fsync`, `fdatasync` |
| status | `stat`, `lstat`, `fstat`, `fstatat`, `access`, `faccessat` (a `file_status`, a `file_kind`) |
| names | `rename`, `rename_noreplace`, `renameat`, `link`, `linkat`, `symlink`, `symlinkat`, `readlink`, `readlinkat`, `realpath`, `unlink`, `unlinkat` |
| directories | `mkdir`, `mkdirat`, `mkdtemp`, `rmdir`, `opendir`, `fdopendir`, `readdir`, `dirfd`, `closedir`, `chdir`, `getcwd` |
| ownership | `chmod`, `fchmod`, `chown`, `fchown`, `lchown`, `umask`, `utimens` |
| file systems | `mount`, `umount` (flags in `mount_flags`, `umount_flags`), `sync` |

The flags of `open` are the raw values of the `ca::fs` options (`fs::access::READ_ONLY`, `fs::create_t::OPEN_VALUE`, ...), defined without `<fcntl.h>`; `fs::descriptor` (layer 6) combines them as typed options instead, and closes the descriptor for you.

```c++
#include "ca/error.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/integers.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	char dir[] = "example_XXXXXX";
	if (!ca::sys::mkdtemp(dir))
		return 1;
	auto here = ca::sys::openat(ca::sys::at::cwd, dir, ca::fs::access::READ_ONLY | ca::fs::directory_t::OPEN_VALUE, 0U);
	if (!here)
		return 2;

	constexpr int create = ca::fs::access::READ_WRITE | ca::fs::create_t::OPEN_VALUE | ca::fs::exclusive_t::OPEN_VALUE
		| ca::fs::cloexec_t::OPEN_VALUE;
	auto fd = ca::sys::openat(*here, "notes.txt", create, 0644U);
	if (!fd || !ca::sys::write_all(*fd, ca::sv::str{"first line\nsecond line\n"}))
		return 3;

	char word[6]{};
	auto got = ca::sys::pread(*fd, ca::span<char>{word}.prefix(6U), 11U);
	if (!got || ca::sv::str{word, *got} != ca::sv::str{"second"})
		return 4;
	auto status = ca::sys::fstat(*fd);
	if (!status || status->size() != 23U || status->kind() != ca::sys::file_kind::regular)
		return 5;
	auto end = ca::sys::seek(*fd, 0, ca::sys::seek_origin::end);
	if (!end || *end != 23 || !ca::sys::close(*fd))
		return 6;

	auto again = ca::sys::openat(*here, "notes.txt", create, 0644U);
	if (again || again.error() != ca::errc::exists)
		return 7;

	auto listing = ca::sys::opendir(dir);
	if (!listing)
		return 8;
	ca::usz entries = 0U;
	for (auto name = ca::sys::readdir(*listing); name && !name->empty(); name = ca::sys::readdir(*listing))
		++entries;
	if (entries != 1U || !ca::sys::closedir(*listing))
		return 9;

	if (!ca::sys::unlinkat(*here, "notes.txt", 0) || !ca::sys::close(*here))
		return 10;
	return ca::sys::rmdir(dir) ? 0 : 11;
}
```

### Details worth knowing

- `read`, `write`, `pread`, `pwrite`, `open` and `ftruncate` retry on EINTR. `read` returns 0 only at end of file; `write` may write less than asked, `write_all` loops until everything is written (and on failure an unknown prefix was).
- `close` releases the descriptor even when it fails, and counts EINTR as success: retrying could close a descriptor another thread was just given.
- `readdir` skips "." and ".." and returns an empty name at the end; the name is valid until the next call on the stream.
- `readlink` writes the target unterminated and returns its length; a length equal to the buffer size may mean truncation.
- `realpath` returns a block to release with `ca::sys::free`.
- `rename_noreplace` fails with `errc::exists` atomically instead of replacing, where the file system supports it.
- The `*at` variants resolve relative paths against an open directory (`sys::at::cwd` for the working directory), which avoids races on paths that change underneath; their flags are in `sys::at` (`symlink_nofollow`, `remove_directory`, ...).
- `mount` and `umount` are Linux only (`errc::not_supported` elsewhere) and need CAP_SYS_ADMIN, failing with `errc::not_permitted` without it; `umount` is umount2.
- `file_status` gives times in nanoseconds since the epoch, permissions as the 07777 bits, and the type as a `file_kind`.

## `fs/`

The flags of an open file as compile-time options (`ca::is_option`, layer 2), in `ca::fs`. Each flag is a tag type (`fs::append_t`) and a constant holding the one-element set (`fs::append`), so flags combine with the option algebra: `fs::readable | fs::create`.

Each option belongs to a domain, which says where the flag lives and when it can change:

| Domain | Options | Changes after open |
|---|---|---|
| `fs::access` | `readable`, `writable` | never |
| `fs::open_flags` | `create`, `exclusive`, `truncate`, `directory`, `nofollow` | never |
| `fs::status_flags` | `append`, `nonblock`, `sync` | yes, shared by duplicates (F_SETFL) |
| `fs::descriptor_flags` | `cloexec`, `clofork` | yes, per descriptor (F_SETFD) |

Every option carries `VALUE` (its bit in the domain), `OPEN_VALUE` (its bit in open's flags, so `sys::open` can take them raw) and `SUPPORTED`. `clofork` is `SUPPORTED` only where the platform has it (`fs::has_clofork`); asking for it elsewhere is `errc::not_supported`. The values are written per platform and checked against `<fcntl.h>` when the library builds.

```c++
#include "ca/fs.hpp"
#include "ca/option_set.hpp"
#include "ca/traits.hpp"

constexpr auto log_file = ca::fs::writable | ca::fs::create | ca::fs::append | ca::fs::cloexec;
using log_flags = decltype(log_file);

static_assert(log_flags::HAS<ca::fs::append_t> && !log_flags::HAS<ca::fs::truncate_t>);
static_assert(log_flags::SUPPORTED);
static_assert(ca::fs::is_fcntl_option<ca::fs::nonblock_t> && !ca::fs::is_fcntl_option<ca::fs::create_t>);

constexpr int raw = ca::fs::access::WRITE_ONLY | ca::fs::create_t::OPEN_VALUE | ca::fs::append_t::OPEN_VALUE;
static_assert((raw & ca::fs::append_t::OPEN_VALUE) != 0);
```

`fs::descriptor` (layer 6) takes these sets as template arguments and checks the combination when it compiles: `exclusive` without `create`, or `truncate` on a read-only file, are compile errors. `fs::is_fcntl_option` selects the options `set()` and `get()` can change on an open descriptor.

## `io/`

Descriptor plumbing beyond plain reads and writes: pipes, waiting on several descriptors, scatter and gather I/O, terminals.

| Function | Does |
|---|---|
| `sys::pipe(flags)` | a new pipe, as `pipe_ends` (`read_end()`, `write_end()`); flags from `ca::fs` |
| `sys::dup2(fd, target)` | makes target a copy of fd (the copy is not close-on-exec) |
| `sys::poll(entries, timeout_ms)` | waits for events on `poll_entry`s; -1 waits forever, 0 not at all |
| `sys::readv(fd, buffers)`, `sys::writev(fd, buffers)` | one call over several `io_buffer`s |
| `sys::isatty(fd)` | whether fd is a terminal |
| `sys::get_terminal_size(fd)` | rows and columns of the terminal fd is attached to |
| `sys::tcgetattr(fd)` | the terminal's settings, as `terminal_settings`; `not_a_terminal` otherwise |
| `sys::tcsetattr(fd, settings, when)` | applies settings `now` (the default), after a `drain`, or with a `flush` of unread input |
| `sys::enter_raw_mode(fd)` | puts the terminal in raw mode; returns the settings it had, to restore |
| `sys::tcgetpgrp(fd)`, `sys::tcsetpgrp(fd, group)` | the foreground process group of the controlling terminal, read or given |

`terminal_settings` is struct termios without `<termios.h>`: the flag words `input()`, `output()`, `control()`, `local()` with their `set_` counterparts, bits from `sys::terminal_input`, `terminal_output`, `terminal_control` and `terminal_local`, and the control characters by slot (`character(slot)`, `set_character(slot, value)`, slots in `sys::terminal_character`). `raw()` is a copy in raw mode, as cfmakeraw makes it. On Linux the settings have the kernel's layout and go to ioctl as they are.

```c++
#include "ca/error.hpp"
#include "ca/io.hpp"

auto main(void) -> int {
	auto previous = ca::sys::enter_raw_mode(0);
	if (!previous)
		return previous.error() == ca::errc::not_a_terminal ? 0 : 1;
	auto raw = ca::sys::tcgetattr(0);
	if (!raw || (raw->local() & ca::sys::terminal_local::echo) != 0U)
		return 2;
	return ca::sys::tcsetattr(0, *previous) ? 0 : 3;
}
```

`poll_events` holds the event bits without `<poll.h>`: `readable`, `writable`, `urgent`, and the reported-only `error`, `hangup` and `invalid`. A `poll_entry` records the events asked for and, after the call, those that occurred (`reported()`, `has(bits)`).

```c++
#include "ca/error.hpp"
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/io.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	auto ends = ca::sys::pipe(ca::fs::cloexec_t::OPEN_VALUE | ca::fs::nonblock_t::OPEN_VALUE);
	if (!ends)
		return 1;

	ca::sys::poll_entry watch[1] = {ca::sys::poll_entry{ends->read_end(), ca::sys::poll_events::readable}};
	auto idle = ca::sys::poll(watch, 0);
	if (!idle || *idle != 0U)
		return 2;

	const ca::sys::io_buffer parts[] = {ca::sv::str{"hello, "}, ca::sv::str{"world"}};
	auto sent = ca::sys::writev(ends->write_end(), parts);
	if (!sent || *sent != 12U)
		return 3;

	auto ready = ca::sys::poll(watch, 1000);
	if (!ready || *ready != 1U || !watch[0].has(ca::sys::poll_events::readable))
		return 4;
	char got[16]{};
	auto read = ca::sys::read(ends->read_end(), got);
	if (!read || ca::sv::str{got, *read} != ca::sv::str{"hello, world"})
		return 5;

	auto empty = ca::sys::read(ends->read_end(), got);
	if (empty || empty.error() != ca::errc::try_again)
		return 6;
	if (ca::sys::isatty(ends->read_end()))
		return 7;
	return ca::sys::close(ends->read_end()) && ca::sys::close(ends->write_end()) ? 0 : 8;
}
```

An `io_buffer` has the layout of `struct iovec`, so an array of them goes to the kernel as is, and it converts from anything a byte span is made from: text, char arrays, strings. The caller closes both ends of a pipe.

## `math/`

The functions of libm whose result IEEE 754 fixes to the bit, for programs linked without libm: libca_runtime's `fmod`, `remainder`, `remquo`, `sqrt`, `floor`, `ceil`, `trunc`, `round`, `roundeven`, `rint`, `nearbyint`, `lrint`, `lround`, `fmin`, `fmax`, `fdim`, `fma`, `ldexp`, `scalbn`, `frexp`, `modf`, `logb`, `ilogb` and `nextafter` (each also with the f and l suffixes; fma not for long double), what compilers lower `__builtin_fmod` and the others to. They are `sys::impl` templates (Linux x86-64), not an interface of their own: a program calls the builtins.

| How | Functions |
|---|---|
| x87 `fprem` / `fprem1` loop on the operands widened, exact | fmod, remainder, remquo |
| the instruction (`sqrtsd`, `fsqrt`, `vfmadd213sd`) | sqrt, fma |
| fraction bits cleared, a unit carried in; `frndint` for long double | floor, ceil, trunc, round, roundeven |
| x + 2^p - 2^p in the current rounding mode; `cvtsd2si`, `fistp` | rint, nearbyint, lrint |
| one final multiply by 2^n; `fscale` | ldexp, scalbn |
| exponent and significand bits | frexp, modf, logb, ilogb, nextafter |

Each gives glibc 2.39's result bit for bit, NaN payloads included, in every rounding mode, and sets errno (ca's last error) as glibc does, checked against it by `tests/sys_exact_math_libc.cpp`. One difference is deliberate: a zero remainder carries x's sign, as IEEE 754 requires, where glibc's remainder can give the other sign when rounding down or up, or for a double divisor below 2^-1020. Without the FMA instruction, fma computes the exact sum in 128-bit integers, rounds it to odd at 64 bits into a long double, then rounds that once to float or double. Transcendental functions (exp, log, sin, pow, ...) are not provided.

## `math/impl/exact_math.hpp`

## `memory/`

Memory from the system: page mappings, and the C allocator for code that must interoperate with it. The allocators of layer 4 (`ca::heap`, `page_allocator`, `libc_allocator`) are built on these; application code normally uses those instead.

### Mappings

| Function | Does |
|---|---|
| `sys::page_size()` | the size of a page |
| `sys::mmap_anonymous(size, protection)` | fresh zeroed pages, private to the process |
| `sys::mmap_file(fd, offset, size, protection, sharing)` | a file's pages, `shared` or `copy_on_write` |
| `sys::mremap(mapping, size, remapping)` | grows or shrinks a mapping, `in_place` or `may_move` |
| `sys::mprotect(region, protection)` | changes the protection of pages |
| `sys::madvise(region, advice)` | `normal`, `random`, `sequential`, `will_need`, `dont_need` |
| `sys::msync(mapping)` | writes a shared file mapping back and waits |
| `sys::munmap(mapping)` | unmaps a mapping, or some pages of one |

A mapping is a `span<byte>`: functions return one and take one, so the size always travels with the address. Regions must be page-aligned; an unaligned one fails with `errc::invalid_argument`. `protection` holds the bits `read`, `write`, `execute` and `none`. On Linux x86-64 the calls go straight to the kernel through `ca::syscall`, without libc.

```c++
#include "ca/error.hpp"
#include "ca/integers.hpp"
#include "ca/memory.hpp"
#include "ca/span.hpp"

auto main(void) -> int {
	const ca::usz page = ca::sys::page_size();
	auto block = ca::sys::mmap_anonymous(4U * page, ca::sys::protection::read | ca::sys::protection::write);
	if (!block)
		return 1;
	ca::span<ca::byte> pages = *block;
	if (pages[page] != 0U)
		return 2;
	pages[page] = 42U;

	auto grown = ca::sys::mremap(pages, 8U * page, ca::sys::remapping::may_move);
	if (!grown || grown->size() != 8U * page || (*grown)[page] != 42U)
		return 3;
	pages = *grown;

	if (!ca::sys::madvise(pages.suffix(4U * page), ca::sys::advice::dont_need))
		return 4;
	if (!ca::sys::mprotect(pages, ca::sys::protection::read))
		return 5;
	auto unaligned = ca::sys::mprotect(pages.sub(1U, page), ca::sys::protection::read);
	if (unaligned || unaligned.error() != ca::errc::invalid_argument)
		return 6;
	return ca::sys::munmap(pages) ? 0 : 7;
}
```

### The C allocator

`sys::mallocarray(count, size)` and `sys::reallocarray(block, count, size)` allocate with the multiplication checked for overflow, aligned to `malloc_alignment`; `sys::free` releases (nullptr does nothing). They exist for blocks that cross into C code, `realpath`'s result for instance.

`move_paths.hpp` exposes the strategies ca's memcpy and memmove take, one function per size class and instruction set (`ca::move_paths::bytes_0_to_15`, `forward`, `stream`, ...), each checking that the size is in its range; benchmarks and tests call them to measure or verify one path alone. The out-of-line ones (`forward` and after) need SSE2: an integer-only build has the inline size classes only.

## `net/`

IPv4 UDP sockets: datagrams between endpoints, on raw syscalls on Linux x86-64 and libc elsewhere. Sockets are plain descriptors, closed with `sys::close`.

| Function | Does |
|---|---|
| `sys::udp_socket(flags)` | a new IPv4 UDP socket; flags from `ca::fs` (cloexec, nonblock) as for `sys::pipe` |
| `sys::bind(fd, endpoint)` | gives the socket its local endpoint; port 0 lets the system pick |
| `sys::local_endpoint(fd)` | the endpoint the socket is bound to |
| `sys::send_to(fd, bytes, endpoint)` | sends one datagram |
| `sys::receive_from(fd, buffer)` | receives one datagram, as a `datagram` (`size`, `from`) |

`ipv4_endpoint` is an address and a port in host order: `ipv4_endpoint{127, 0, 0, 1, 8000}`, `ipv4_endpoint::loopback(port)`, `ipv4_endpoint::any(port)`; `address()`, `octet(i)`, `port()`. On a nonblocking socket, `send_to` with a full buffer and `receive_from` with nothing queued fail with `errc::try_again`; `sys::poll` waits for either. Interrupted calls are restarted.

```c++
#include "ca/file.hpp"
#include "ca/net.hpp"

auto main(void) -> int {
	auto server = ca::sys::udp_socket(0);
	auto client = ca::sys::udp_socket(0);
	if (!server || !client || !ca::sys::bind(*server, ca::sys::ipv4_endpoint::loopback(0U)))
		return 1;
	auto address = ca::sys::local_endpoint(*server);
	if (!address || address->port() == 0U)
		return 2;
	const ca::byte hello[] = {'h', 'i'};
	auto sent = ca::sys::send_to(*client, hello, *address);
	if (!sent || *sent != 2U)
		return 3;
	ca::byte buffer[16];
	auto got = ca::sys::receive_from(*server, buffer);
	if (!got || got->size != 2U || buffer[1] != 'i' || got->from.address() != 0x7F000001U)
		return 4;
	return ca::sys::close(*client) && ca::sys::close(*server) ? 0 : 5;
}
```

## `process/`

Processes and signals: starting programs, waiting for them, identities, resource limits and usage, and signal handling.

### Starting and waiting

| Function | Does |
|---|---|
| `sys::posix_spawn(path, argv, envp, actions, options)` | starts a program as a child, returns its pid |
| `sys::posix_spawnp(file, argv, envp, actions, options)` | the same, looking file up in PATH |
| `sys::fork()` | duplicates the process: the child's pid in the parent, 0 in the child |
| `sys::execve`, `sys::execvp` | replace the process image |
| `sys::waitpid(pid)` | waits for a child and reaps it: a `wait_status` |
| `sys::try_waitpid(pid)` | the same without blocking: nothing while the child runs |
| `sys::exit(status)`, `sys::exit_immediately(status)` | end the process, with or without atexit handlers |

`argv` and `envp` are null-terminated arrays of mutable C strings, as POSIX takes them; a null `envp` passes the current environment. A `wait_status` tells which child ended (`child()`, what a wait for -1 or `-group` needs) and how: `exit_code()` and `signal()` are optionals, `succeeded()` means exit code 0.

`spawn_actions` lists descriptor changes the child applies before running the program (dup2, close, open), so a child's standard streams can be redirected without fork. It follows ca's explicit lifecycle: `make()` builds it, `cleanup()` frees it; it moves but does not copy. `spawn_options` is a plain value (the default changes nothing): `set_process_group(group)` has the child join group first, or with 0 lead a new one, as a shell starts a job.

```c++
#include "ca/file.hpp"
#include "ca/fs.hpp"
#include "ca/integers.hpp"
#include "ca/io.hpp"
#include "ca/process.hpp"
#include "ca/span.hpp"
#include "ca/sv.hpp"

auto main(void) -> int {
	char sh[] = "sh";
	char dash_c[] = "-c";
	char script[] = "printf hello; exit 3";
	char* const argv[]{sh, dash_c, script, nullptr};

	auto ends = ca::sys::pipe(ca::fs::cloexec_t::OPEN_VALUE);
	if (!ends)
		return 1;
	auto actions = ca::sys::spawn_actions::make();
	if (!actions || !actions->add_dup2(ends->write_end(), 1))
		return 2;
	auto child = ca::sys::posix_spawnp("sh", argv, nullptr, &*actions);
	if (!child || !actions->cleanup() || !ca::sys::close(ends->write_end()))
		return 3;

	char out[16]{};
	ca::usz total = 0U;
	for (;;) {
		auto got = ca::sys::read(ends->read_end(), ca::span<char>{out}.without_prefix(total));
		if (!got)
			return 4;
		if (*got == 0U)
			break;
		total += *got;
	}
	auto status = ca::sys::waitpid(*child);
	if (!status || status->exit_code() != 3 || status->succeeded())
		return 5;
	return ca::sv::str{out, total} == ca::sv::str{"hello"} && ca::sys::close(ends->read_end()) ? 0 : 6;
}
```

A forked child calls `exit_immediately`, which runs no handler and flushes nothing: the parent's buffered output would otherwise be written twice.

### Signals

`sys::signals` names the signal numbers without `<signal.h>` (`interrupt`, `terminate`, `kill`, `child`, `pipe`, `user1`, ..., and for job control `stop`, `resume`, `terminal_stop`, `background_read`, `background_write`, `window_resize`). `sys::sigaction(signal, handler)` installs a handler with interrupted calls restarted, or a `signal_disposition` (`default_action`, `ignore`). `signal_set` is a constexpr set of signal numbers for `sigprocmask` (`block`, `unblock`, `replace`) and `sigwait`, which takes a blocked signal synchronously: the safe way to handle signals without running code inside a handler.

```c++
#include "ca/process.hpp"

auto main(void) -> int {
	ca::sys::signal_set set;
	set.add(ca::sys::signals::user1);
	auto previous = ca::sys::sigprocmask(ca::sys::mask_change::block, set);
	if (!previous)
		return 1;
	if (!ca::sys::kill(ca::sys::getpid(), ca::sys::signals::user1))
		return 2;
	auto taken = ca::sys::sigwait(set);
	if (!taken || *taken != ca::sys::signals::user1)
		return 3;
	return ca::sys::sigprocmask(ca::sys::mask_change::replace, *previous) ? 0 : 4;
}
```

`sigwaitinfo(set)` takes the signal with a `signal_info`: its number, how it was sent (`code()`, `signal_codes::user` or `queue`), the sender's pid and uid, and the value `sigqueue(pid, signal, value)` carried. `sigtimedwait(set, nanoseconds)` waits at most that long and fails with `errc::timed_out`; 0 polls. Both, and `sigqueue`, are Linux-only (`errc::not_supported` elsewhere).

`sigaction(signal, handler, flags)` takes `sigaction_flags` (`restart`, `on_alternate_stack`, `no_defer`, `reset_handler`) instead of the default restart. A handler meant to survive a stack overflow runs `on_alternate_stack`, on the memory `sigaltstack(stack)` gives the thread; an empty span removes it, which a thread must do before that memory goes away.

```c++
#include "ca/process.hpp"
#include "ca/span.hpp"

static char alternate[65536];

static auto on_overflow(int) -> void {
	ca::sys::exit_immediately(70);
}

auto main(void) -> int {
	if (!ca::sys::sigaltstack(ca::span<char>{alternate}))
		return 1;
	if (!ca::sys::sigaction(ca::sys::signals::segv, on_overflow, ca::sys::sigaction_flags::on_alternate_stack))
		return 2;
	ca::sys::signal_set set;
	set.add(ca::sys::signals::user1);
	if (!ca::sys::sigprocmask(ca::sys::mask_change::block, set))
		return 3;
	if (!ca::sys::sigqueue(ca::sys::getpid(), ca::sys::signals::user1, 7))
		return 4;
	auto info = ca::sys::sigtimedwait(set, 1000000000);
	return info && info->queued() && info->value() == 7 ? 0 : 5;
}
```

### Identity and resources

`getpid`, `getppid`, `getuid`, `geteuid`, `getgid`, `getegid`, `getpgid`, `setpgid` and `setsid` cover process identity and groups. `getrlimit` and `setrlimit` read and set a `resource_limit` (soft `current()` and hard `maximum()`, `UNLIMITED` for none) of a `resource` (`open_files`, `stack_size`, `address_space`, ...). `getrusage` reports a `resource_usage` of the process or of its waited-for children: CPU times in nanoseconds, peak resident memory, page faults and context switches.

```c++
#include "ca/process.hpp"

auto main(void) -> int {
	auto files = ca::sys::getrlimit(ca::sys::resource::open_files);
	if (!files || files->current() == 0U)
		return 1;
	if (!ca::sys::setrlimit(ca::sys::resource::open_files, *files))
		return 2;
	auto usage = ca::sys::getrusage(ca::sys::usage_target::process);
	return usage && usage->max_resident() > 0U ? 0 : 3;
}
```

Conversions between ca's portable process types and the platform's, declared with opaque pointers so that no header names a system type, and defined in `.cpp` files:

## `random/`

`sys::getentropy(buffer)` fills a buffer of any size from the kernel's secure random source, fetched 256 bytes at a time (the limit of one getentropy call). It is the right source for keys, nonces and hash seeds; it is too slow to call per random number, so seed a fast generator from it instead.

```c++
#include "ca/integers.hpp"
#include "ca/random.hpp"
#include "ca/span.hpp"

[[nodiscard]] static auto random_seed(void) noexcept -> ca::u64 {
	ca::byte bytes[8]{};
	if (!ca::sys::getentropy(bytes))
		return 0x9E37'79B9'7F4A'7C15U;
	ca::u64 seed = 0U;
	for (const ca::byte b : bytes)
		seed = seed << 8U | b;
	return seed;
}

auto main(void) -> int {
	ca::byte key[1000]{};
	if (!ca::sys::getentropy(key))
		return 1;
	ca::usz zeros = 0U;
	for (const ca::byte b : key)
		zeros += b == 0U ? 1U : 0U;
	return zeros < 40U && random_seed() != random_seed() ? 0 : 2;
}
```

## `sync/`

Synchronization between threads, each over one or two futex words (`sys::futex_wait`, `futex_wake`): no allocation, no kernel object, constant-initialized, trivially destructible. Nothing here fails except a timed wait, with `errc::timed_out`, as I/O fails.

| Type | Does |
|---|---|
| `ca::mutex` | lock, try_lock, lock_until/lock_for, unlock; not recursive |
| `ca::condition` | wait/wait_until/wait_for on a held mutex, with or without a predicate; notify_one, notify_all |
| `ca::once` | call(f): f runs once among every caller; a failed `result<void>` lets the next call retry |
| `ca::latch` | count_down, wait, try_wait, arrive_and_wait: a one-shot countdown |
| `ca::semaphore` | acquire, try_acquire, acquire_until/acquire_for, release(n) |

Deadlines are `sys::now(clock::monotonic)` nanoseconds; each `*_for` takes a duration in nanoseconds instead. A wait may come back without a notify, so `condition` loops on a predicate when given one.

```c++
#include "ca/sync.hpp"
#include "ca/time.hpp"

static constinit ca::mutex lock;
static constinit ca::condition changed;
static constinit ca::once setup;
static int ready = 0;

auto main(void) -> int {
	if (!setup.call([] { ready = 1; }) || !setup.is_done())
		return 1;
	lock.lock();
	changed.wait(lock, [] { return ready == 1; });
	const bool timed_out = !changed.wait_for(lock, 1000000);
	lock.unlock();
	if (!timed_out)
		return 2;
	ca::semaphore slots{1U};
	if (!slots.try_acquire() || slots.try_acquire())
		return 3;
	slots.release();
	ca::latch done{2U};
	done.count_down(2U);
	return done.try_wait() ? 0 : 4;
}
```

Unlocking a mutex nobody holds traps, as does counting a latch below zero. A thread that traps while holding a mutex leaves it locked; `ca::locked` (layer 4) unlocks on the way out.

## `syscall/`

`ca::syscall`: the kernel's own entry points, without libc. `ca::sys` calls these wherever the target has a table, which is how ca reaches the kernel without the C library; user code should prefer the typed `ca::sys` wrappers, since these check nothing beyond the argument count and kind.

- `syscall::invoke(number, args...)` makes any syscall with up to six arguments, each an integer, an enum or a pointer (`is_argument`), and returns the kernel's result or its errno as the error.
- With a table (`syscall::has_table`, Linux x86-64 today), `syscall::number::<name>` gives each number and `syscall::<name>(args...)` each call, with the kernel's own parameter names and arity: a call with the wrong number of arguments does not compile.

```c++
#include "ca/error.hpp"
#include "ca/process.hpp"
#include "ca/syscall.hpp"

auto main(void) -> int {
	if constexpr (ca::syscall::has_table) {
		auto pid = ca::syscall::getpid();
		if (!pid || *pid != ca::sys::getpid())
			return 1;
		auto same = ca::syscall::invoke(ca::syscall::number::getpid);
		if (!same || *same != *pid)
			return 2;

		int ends[2]{-1, -1};
		if (!ca::syscall::pipe2(ends, 0))
			return 3;
		auto written = ca::syscall::write(ends[1], "ok", 2U);
		char got[2]{};
		auto read = ca::syscall::read(ends[0], got, sizeof got);
		if (!written || *written != 2 || !read || *read != 2 || got[0] != 'o')
			return 4;
		if (!ca::syscall::close(ends[0]) || !ca::syscall::close(ends[1]))
			return 5;

		auto closed = ca::syscall::close(-1);
		if (closed || closed.error() != ca::errc::bad_descriptor || ca::sys::last_error() != ca::errc::bad_descriptor)
			return 6;
	}
	return 0;
}
```

A failing call stores its errno in `sys::last_error()` as it returns: one thread-local store, no call. On Linux x86-64, aarch64 and riscv64 the syscall is the trap instruction inlined at the call site; on other Linux CPUs `invoke` goes through libc's `syscall(2)`, and on macOS, whose syscall numbers are not a stable interface, it fails with `errc::not_supported`.

The table is generated by `tooling/gen_syscalls.py` (`make syscalls`) from the build headers of the running kernel, so it contains exactly the syscalls that kernel implements; generated files are never edited by hand.

## `syscall/impl/`

`enter(number, args...)` is the instruction that enters the kernel. On Linux x86-64, aarch64 and riscv64 it is inline assembly with one overload per argument count, 0 to 6, each binding exactly the registers it uses through register variables, so the compiler loads the arguments in place and keeps everything else live across the call. Memory is clobbered, since the kernel reads and writes through the pointers it is given. It returns the raw kernel value: -errno, between -4095 and -1, on failure; `invoke` turns that into a `ca::result`.

`read_own(address, out)` copies the process's own memory through `process_vm_readv`, which fails instead of faulting on an unmapped address: the backtrace walks frame records with it, and `elf::image::program()` reads the ELF header of a static PIE. It goes through `enter`, so a failure leaves the last error as it was.

`inline_entry` tells whether `enter` is the inlined instruction (true on those three CPUs) or a call to libc's `syscall(2)`. Functions that must not return, such as `exit`, are generated as `[[noreturn]]` and end in `ca::unreachable()` after the instruction.

## `text/`

Numbers and text without the C library: integers parsed from text (below), and floating point to text: the shortest digits by Ryu, all others exact (every decimal digit of the double, rounded to nearest, ties to even), digit for digit what glibc's printf prints. Built on `1-primitives/floats/impl/` (shortest_decimal, exact_decimal).

- `sys::format_float(buffer, value, conversion, precision, alternate)` writes value as printf's `%f`, `%e`, `%g` or `%a` (and their capitals) would, with a precision when it is not negative and the `#` flag when alternate is set. Width and sign flags are the formatter's job.
- `sys::format_float_shortest(buffer, value)` writes the fewest `%g` digits that read back as the same value: `0.1` gives "0.1", not "0.10000000000000001". The `f32` overload round-trips as an `f32`, so `0.1F` also gives "0.1". This is what `{}` prints for a float.

Both write into a char span, NUL-terminate it (it must not be empty) and return the length, at most `buffer.size() - 1`.

```c++
#include "ca/floats.hpp"
#include "ca/sv.hpp"
#include "ca/text.hpp"

auto main(void) -> int {
	char buffer[32];
	ca::usz n = ca::sys::format_float_shortest(buffer, 0.1);
	if (ca::sv::str{buffer, n} != ca::sv::str{"0.1"})
		return 1;
	n = ca::sys::format_float_shortest(buffer, ca::f32{0.1F});
	if (ca::sv::str{buffer, n} != ca::sv::str{"0.1"})
		return 2;
	n = ca::sys::format_float(buffer, 3.14159, 'f', 2, false);
	if (ca::sv::str{buffer, n} != ca::sv::str{"3.14"})
		return 3;
	n = ca::sys::format_float(buffer, 1500.0, 'e', -1, false);
	return ca::sv::str{buffer, n} == ca::sv::str{"1.500000e+03"} ? 0 : 4;
}
```

The decimal point is always '.', whatever setlocale says. Two outputs differ from glibc on purpose: `%#g` when rounding carries into a new exponent keeps all its digits, as C specifies (glibc prints `1.e+02` for 99.5 at `%#.2g`, ca `1.0e+02`), and the shortest form of a subnormal is truly the shortest (`5e-324`, where `%.15g` gave 15 digits).

### Integers from text

`sys::parse_integer<T>(text, base)` reads the whole of text as an integer of any integer type but bool and the character types, in base 10 or any base 2 to 36: an optional `+` or `-` (`-` for a signed T only) then digits, as `std::from_chars` takes them but with a `+` allowed and no text left over. It fails with `errc::invalid_argument` for anything else (empty text, spaces, an `0x` prefix, a stray character) and `errc::out_of_range` when the value does not fit in T, the minimum of a signed T included. constexpr, header only.

```c++
#include "ca/error.hpp"
#include "ca/integers.hpp"
#include "ca/text.hpp"

auto main(void) -> int {
	auto status = ca::sys::parse_integer<int>("-42");
	if (!status || *status != -42)
		return 1;
	auto mask = ca::sys::parse_integer<ca::u32>("1ff", 16);
	if (!mask || *mask != 0x1FFU)
		return 2;
	auto big = ca::sys::parse_integer<ca::u8>("256");
	return !big && big.error() == ca::errc::out_of_range ? 0 : 3;
}
```

## `thread/`

Threads, futexes, yield, and per-thread slots with an exit callback.

`sys::thread::make(entry, argument)` starts a thread on raw clone: one mapping holds a guard page, its stack, a control block and its own TLS area. When entry returns the thread runs its `thread_local` destructors and key destructors, then leaves. `join()` waits for that and unmaps; `cleanup()` does the same and also accepts a thread already joined. Results travel through argument. It works only in programs started by libca_runtime: in a program started by libc, libc owns `%fs`, and make fails with `errc::not_supported`.

`sys::futex_wait(word, expected)` sleeps while a `ca::atomic<u32>` holds expected, until a `sys::futex_wake(word, count)`; `futex_wait_until(word, expected, deadline)` gives up with `errc::timed_out` at a monotonic deadline. Either may return early, so callers loop on the word. Words are process-private. Linux only; elsewhere a wait yields once, which keeps every loop correct but spinning. The primitives built on them are in `sync/`. `sys::yield()` gives the CPU to another runnable thread.

The slots are the POSIX thread-specific keys, reduced to what C++ `thread_local` cannot do.

`sys::thread_key_create(on_exit)` makes a slot holding one pointer per thread, null in each. When a thread other than the main one exits with a non-null value in the slot, `on_exit(value)` runs in that thread, the slot cleared first. `sys::thread_key_set(key, value)` stores the calling thread's value. Keys are never deleted.

There is no getter on purpose: the data itself lives in a `thread_local` variable, which is faster to reach, and the key only arranges the cleanup. `ca::heap` uses this to hand a dying thread's memory back, and `ca::io::out()` to flush a thread's buffered output when it ends.

```c++
#include "ca/thread.hpp"

namespace {

	struct thread_cache final {
		int items;
	};

	constinit thread_local thread_cache* cache = nullptr;

	auto release_cache(void* const value) noexcept -> void {
		static_cast<thread_cache*>(value)->items = 0;
	}

} // namespace

auto main(void) -> int {
	static thread_cache main_cache{3};
	auto key = ca::sys::thread_key_create(&release_cache);
	if (!key)
		return 1;
	cache = &main_cache;
	return ca::sys::thread_key_set(*key, cache) && cache->items == 3 ? 0 : 2;
}
```

The callback does not run for the main thread, which ends with the process; flush or release main-thread state from `main` or an atexit handler instead.

## `time/`

Clocks, sleeping and the calendar. Time is a plain `ca::i64` count: nanoseconds for clocks, seconds since the epoch for calendar conversions.

| Function | Does |
|---|---|
| `sys::now(clock)` | the time of a clock in nanoseconds; never fails |
| `sys::resolution(clock)` | the smallest step that clock reports |
| `sys::sleep_for(ns)` | suspends the thread, resuming after signals until the time is up |
| `sys::utc_time(seconds)`, `sys::local_time(seconds)` | a `calendar_time` in UTC or the local zone |
| `sys::utc_seconds(time)` | back from a `calendar_time` read as UTC |

The clocks are `realtime` (since the epoch, may jump when the system clock is set), `monotonic` (from an arbitrary point, never goes back: measure durations with it), `process_cpu` and `thread_cpu` (CPU time consumed).

```c++
#include "ca/integers.hpp"
#include "ca/time.hpp"

auto main(void) -> int {
	const ca::i64 start = ca::sys::now(ca::sys::clock::monotonic);
	if (!ca::sys::sleep_for(1'000'000))
		return 1;
	const ca::i64 elapsed = ca::sys::now(ca::sys::clock::monotonic) - start;
	if (elapsed < 1'000'000)
		return 2;

	auto day = ca::sys::utc_time(951825599);
	if (!day || day->year() != 2000 || day->month() != 2 || day->day() != 29 || day->weekday() != 2)
		return 3;
	auto back = ca::sys::utc_seconds(*day);
	if (!back || *back != 951825599)
		return 4;

	const ca::sys::calendar_time thirteenth{2025, 13, 1, 0, 0, 0, 0, 0, 0, false};
	auto carried = ca::sys::utc_seconds(thirteenth).and_then([](const ca::i64 s) noexcept {
		return ca::sys::utc_time(s);
	});
	return carried && carried->year() == 2026 && carried->month() == 1 ? 0 : 5;
}
```

A `calendar_time` has `year()`, `month()` (1 to 12), `day()` (1 to 31), `hour()`, `minute()`, `second()`, `weekday()` (0 is Sunday), `year_day()` (1 to 366), `utc_offset()` in seconds and `daylight_saving()`. `utc_seconds` reads only year to second, and lets fields out of range carry over, so adding 1 to the month or 40 to the day and converting back gives the right date. `local_time` follows `TZ`, or `/etc/localtime` when it is unset. Years that do not fit fail with `errc::out_of_range`.

## `trace/`

Error traces: where an error came from, and what each caller was doing when it passed through. A `ca::error` is an int code plus the number of a trace; the trace itself lives in the calling thread, so returning a traced error costs no more than returning an untraced one.

| Function | Does |
|---|---|
| `trace::fail(error, message)` | starts the thread's trace with error, first frame at the caller |
| `trace::context(error, message)` | adds a frame at the caller to error's trace |
| `trace::of(error)` | the `record` of error: its frames, origin first |
| `ca::print_trace(error)` | prints the error and its trace (layer 6) |

`fail` and `context` return a `ca::failure`, so they sit directly in a return statement. Each frame records the function, file and line through `ca::source_location`, without a macro. Messages must outlive the trace, so they are literals; `ca::context` (layer 5) adds formatted messages, and `ca::report` keeps a trace beyond the thread.

```c++
#include "ca/error.hpp"
#include "ca/result.hpp"
#include "ca/sv.hpp"
#include "ca/trace.hpp"

[[nodiscard]] static auto open_config(const bool present) noexcept -> ca::result<int> {
	if (!present)
		return ca::trace::fail(ca::errc::no_entry, "config.toml");
	return 3;
}

[[nodiscard]] static auto load(const bool present) noexcept -> ca::result<int> {
	auto config = open_config(present);
	if (!config)
		return ca::trace::context(config.error(), "opening config");
	return *config + 1;
}

auto main(void) -> int {
	auto r = load(false);
	if (r || r.error() != ca::errc::no_entry || r.error().trace() == 0U)
		return 1;
	const ca::trace::record record = ca::trace::of(r.error());
	if (record.frames().size() != 2U || record.dropped() != 0U)
		return 2;
	if (record.frames()[0].message() != ca::sv::str{"config.toml"})
		return 3;
	if (record.frames()[1].message() != ca::sv::str{"opening config"})
		return 4;
	return record.frames()[1].where().line() == 15U ? 0 : 5;
}
```

Printed with `{}` or `ca::print_trace`, a record reads:

```text
No such file or directory
  at open_config (app.cpp:8): config.toml
  at load (app.cpp:15): opening config
```

### One trace per thread

Each thread holds one trace, of at most 32 frames; later frames are counted in `dropped()`. `fail` replaces it, so a trace follows the error currently being returned. `context` on an error that does not carry the thread's current trace (one made by hand, returned by a system call, or from another thread) starts a new trace instead of extending a wrong one, and `of` returns no frames for it. A `record` borrows from the thread's trace and stays valid until the thread starts another.

Traps join the same trace: when a trap fails a context (`ca::with`), the context's error carries a frame with the trap's reason, and `result::raise` adds an "error raised" frame.

### Backtraces

A trap also leaves the calls that led to it. Before the trap unwinds, while its frames are still alive, the context taking it attaches a `trace::backtrace` to the error's trace: `trace::of(e).backtrace()` returns its addresses, and the printed trace ends with them. Only the first trap a trace meets keeps one, the trap nearest the origin.

| Function | Does |
|---|---|
| `trace::backtrace::capture()` | the calls leading to the caller, the caller first |
| `trap.backtrace()` | in a context's `handles`, the calls leading to the trap (layer 4) |
| `trace::attach(error, backtrace)` | gives error's trace a backtrace, unless it has one |
| `record::backtrace()` | the addresses attached to the trace, empty when none |

```c++
#include "ca/debug.hpp"
#include "ca/trace.hpp"
#include "ca/with.hpp"

[[gnu::noinline]] static auto check(const int value) noexcept -> void {
	if (value < 0)
		ca::trap("negative");
}

auto main(void) -> int {
	auto done = ca::with([](void) noexcept { check(-1); }, [](const ca::error*) noexcept {});
	if (done)
		return 1;
	const ca::trace::record record = ca::trace::of(done.error());
	if (record.backtrace().empty())
		return 2;
	const ca::trace::backtrace here = ca::trace::backtrace::capture();
	return here.empty() ? 3 : 0;
}
```

```text
State not recoverable
  trapped: negative
  backtrace:
    #0 exe+0x1a2f
    #1 exe+0x1b88
    #2 0x7f3c2a42a1c9
```

The walk follows frame pointers, so code built without them (`-fno-omit-frame-pointer -mno-omit-leaf-frame-pointer`; ca's debug builds keep them, `make FRAME_POINTERS=1` in release) gives the first frame right and stops or strays after it. Every read goes through the kernel (`process_vm_readv`), so a broken chain ends the walk instead of crashing the program. An address inside the executable prints relative to where it is loaded, as `addr2line -f -C -e app 0x1a2f` takes it; each points inside its call instruction. Linux x86-64 only; elsewhere backtraces are empty.

The calls leading to the first trap the trace met (see ca::trace::backtrace), empty when none.

## `trace/impl/`

The per-thread trace behind `ca::trace`.

- `trace_state.hpp`: the thread's one trace, a `constinit thread_local` record of the error it follows (its trace number and code) and its first `CAPACITY` frames (32), later ones only counted in `dropped`. `start` replaces it for a new error and returns that error numbered with it; `push` appends a frame. Trace numbers come from one process-wide atomic counter, never 0, so an error from an older trace or from another thread is recognized as stale rather than shown with the wrong frames.
- `display_trace.hpp`: the text form of a trace, shared by `ca::print_trace`, the `{}` formatting of a `trace::record` and `ca::report`: the error's message, then one line per frame, origin first, `  at function (file:line): message`, or `  trapped: message` for a frame without a location (a trap that left for a context), and a last line counting dropped frames. It writes through any `W` with `put(char)` and `put(sv::str)`, so layer 3 needs no formatter.
