Layer 4: how objects are created, owned, copied and destroyed without exceptions, and where their memory comes from (`memory/`).

### Acquisition, initialisation, cleanup

ca has no RAII for resources: a constructor cannot return a failure, so nothing that can fail happens in one. An object goes through three steps, each reporting its own failure.

- Acquisition: `T::make(args...) -> result<T>` does what can fail (allocating, opening, copying), then builds the T with a constructor that cannot fail. `ca::make<T>(args...)` calls it; a type without one is built by its constructor, `T(ca::error&, args...)` when it has one (the constructor reports through the error and `make` returns it), else `T(args...)`. An allocator-aware type also has `make_in(allocator, args...)`, which `ca::make_in` calls.
- Initialisation: constructors only initialize. They acquire nothing.
- Cleanup: a type owning resources (memory, descriptors, mappings) is `ca::is_cleanable`: its `cleanup() -> result<void>` releases everything it owns and reports a failure, such as a close or a flush that failed. Its destructor remains only as a failsafe that releases silently what a skipped `cleanup()` left.

`make` and `make_in` are the acquisition step of every ca type, the names `ca::make` and `ca::make_in` call: `arena::make()`, `str::make(text)`, `slice<T>::make(view)`. When acquiring does more than build the object, a wrapper of `make` names what happens: `fs::descriptor::open( path, options)` opens a file, `io::buffered_reader::over(fd, ...)` borrows a descriptor and `adopt(descriptor, ...)` takes one. A factory that is not `make` has its own name when its arguments do not say what it builds from: `path::cwd()`, `path::home()`, `hashmap::from_keys( keys, value)` (Python's dict.fromkeys), `report::of(error)`. `fs::descriptor::adopt(fd)` and `unique<T>::adopt(object, allocator)` take ownership of something already acquired and cannot fail.

Moving onto a ca owner that still holds something whose release can fail (a descriptor, bytes not yet flushed, elements with a `cleanup()`) traps, so a forgotten cleanup shows up instead of hiding a lost error; an owner holding only memory, which frees without failing, frees it. This is how ca's own types behave, not a requirement on yours: containers never assign over a live element (they move-construct, and swap or reverse assign only onto an element just moved from).

```c++
#include "ca/error.hpp"
#include "ca/integers.hpp"
#include "ca/is_cleanable.hpp"
#include "ca/make.hpp"
#include "ca/result.hpp"
#include "ca/slice.hpp"
#include "ca/utility.hpp"

class counter final {
	private:
		int _limit;
		int _count;

	public:
		counter(ca::error& error, const int limit) noexcept
		: _limit{limit}, _count{0} {
			if (limit <= 0)
				error = ca::errc::invalid_argument;
		}

		[[nodiscard]] auto tick(void) noexcept -> bool {
			return ++_count <= _limit;
		}
};

class buffer final {
	private:
		ca::slice<char> _bytes;

		explicit buffer(ca::slice<char>&& bytes) noexcept
		: _bytes{ca::move(bytes)} {
		}

	public:
		[[nodiscard]] static auto make(const ca::usz size) noexcept -> ca::result<buffer> {
			auto bytes = ca::slice<char>::make(size);
			if (!bytes)
				return bytes.propagate();
			return buffer{ca::move(*bytes)};
		}

		[[nodiscard]] auto size(void) const noexcept -> ca::usz {
			return _bytes.size();
		}

		[[nodiscard]] auto cleanup(void) noexcept -> ca::result<void> {
			return _bytes.cleanup();
		}
};

static_assert(!ca::is_cleanable<counter> && ca::is_cleanable<buffer>);

auto main(void) -> int {
	auto bad = ca::make<counter>(0);
	if (bad || bad.error() != ca::errc::invalid_argument)
		return 1;
	auto made = ca::make<counter>(2);
	if (!made || !made->tick() || !made->tick() || made->tick())
		return 2;
	auto bytes = ca::make<buffer>(64U);
	if (!bytes || bytes->size() != 64U)
		return 3;
	return bytes->cleanup() ? 0 : 4;
}
```

Copies are explicit too: `ca::is_clonable` types have `clone() const -> result<T>`, a copy that may fail (it allocates), which containers use instead of a copy constructor.

### Owning one object

`ca::unique<T, A>` owns one T in memory from allocator A (`ca::heap` by default), like `std::unique_ptr` but built through `make` or `ca::make_in`, cleaned with `cleanup()` (which runs T's own cleanup first), and cloned with `clone()`. Over a stateless allocator it is one pointer wide.

`ca::make_in<T>(source, args...)` builds an allocator-aware T over any allocator or allocator resource: `ca::make_in<ca::unique<T>>(ca::heap{}, ...)` on the heap, or `ca::make_in< ca::dynamic_array<int>>(arena)` in an arena, the type rebound to that allocator.

```c++
#include "ca/make_in.hpp"
#include "ca/memory.hpp"
#include "ca/unique.hpp"
#include "ca/utility.hpp"

struct node final {
	int value;
	explicit node(const int v) noexcept : value{v} {
	}
};

auto main(void) -> int {
	auto made = ca::make_in<ca::unique<node>>(ca::heap{}, 7);
	if (!made || (*made)->value != 7)
		return 1;
	ca::unique<node> owner = ca::move(*made);
	auto copy = owner.clone();
	if (!copy || (*copy)->value != 7 || !copy->cleanup())
		return 2;

	auto arena = ca::arena::make();
	if (!arena)
		return 3;
	auto in_arena = ca::make_in<ca::unique<node>>(*arena, 9);
	if (!in_arena || (*in_arena)->value != 9 || !in_arena->cleanup())
		return 4;
	return owner.cleanup() && arena->cleanup() ? 0 : 5;
}
```

### Contexts

A context is Python's `with` statement for a world without exceptions: setup, a body, and a leave step that always runs, told whether the body failed. Every `ca::trap` reached inside the body (an out-of-range index, a failed result read, an explicit trap) unwinds to the context, which fails with that error instead of ending the program.

`ca::with(enter, leave, args...)` builds one from two callables; `ca::context_manager<Self>` is the CRTP base for a reusable context class with `enter(args...)` and `leave(const E* error)`, run by `self.run(args...)` or `ca::ctx<Self>::run(args...)`.

```c++
#include "ca/context_manager.hpp"
#include "ca/dynamic_array.hpp"
#include "ca/error.hpp"
#include "ca/with.hpp"

struct job final : ca::context_manager<job> {
	int left = 0;
	bool failed = false;

	auto enter(ca::dynamic_array<int>& values, const ca::usz index) noexcept -> void {
		values[index] = 1;
	}

	auto leave(const ca::error* const error) noexcept -> void {
		++left;
		failed = error != nullptr;
	}
};

auto main(void) -> int {
	ca::dynamic_array<int> values{};
	if (!values.append(0))
		return 1;
	job j{};
	if (!j.run(values, 0U) || j.failed)
		return 2;
	auto out_of_range = j.run(values, 5U);
	if (out_of_range || out_of_range.error() != ca::errc::not_recoverable || !j.failed || j.left != 2)
		return 3;

	int entered = 0;
	auto done = ca::with([&entered](const int n) noexcept { entered = n; },
		[](const ca::error*) noexcept {}, 3);
	return done && entered == 3 && values.cleanup() ? 0 : 4;
}
```

A trap skips the destructors of the frames it unwinds: what they owned leaks, so `leave` is where a context releases what `enter` acquired. Inside a context, reading a failed result fails the context with that result's error, so a body can be written as straight-line code with `*r` and still report the first error that happened.

### Which context takes a trap

A trap runs in two phases. First, at the trap site and before anything unwinds, each context from the innermost outward decides on it through `handles(const ca::trapped&) -> ca::verdict`: `take` it, `pass` it to an outer context, or `resume` the code (`ca::ask` only). Then every context passed runs its `leave`, innermost first, and the trap unwinds to the one that took it. A context without `handles` takes every trap, as before. No context taking it stops the program right at the trap, with every frame intact.

| Piece | Role |
|---|---|
| `handles(const ca::trapped&)` | optional: decides at the trap site; `ca::handler{f}` for `ca::with` |
| `ca::trapped` | the trap: `reason()`, `where()`, `error()`, `as<E>()`, `resumable()`, `backtrace()` |
| `ca::verdict` | `take`, `pass`, `resume` |
| `leave(error, ca::outcome)` | optional second parameter: `succeeded`, `taken` or `passed` |
| `ca::ask(reason, error)` | a trap the caller can come back from: true when a context resumed it |

A context passed over still runs `leave`, with outcome `passed`, and its `run` never returns: the trap goes on to the outer context, so `leave` must release everything. `handles`, and `leave` when passed, run while the trap is in flight and must not trap: that stops the program.

`ca::ask` is for code written to carry on: it returns true when a context resumed it (it fixed the cause, check again) and false when none took it (fail the usual way). Contexts without `handles` pass it; one that answers `take` unwinds there as for a trap.

```c++
#include "ca/ask.hpp"
#include "ca/context_manager.hpp"
#include "ca/debug.hpp"
#include "ca/error.hpp"
#include "ca/handler.hpp"
#include "ca/outcome.hpp"
#include "ca/trapped.hpp"
#include "ca/with.hpp"

struct pool final {
	int free;
	int spare;
};

static auto take(pool& from) noexcept -> ca::result<void> {
	while (from.free == 0) {
		if (!ca::ask("pool empty", ca::errc::out_of_memory))
			return ca::failure{ca::errc::out_of_memory};
	}
	--from.free;
	return {};
}

struct refill final : ca::context_manager<refill> {
	pool* from = nullptr;
	ca::outcome ended = ca::outcome::succeeded;

	auto handles(const ca::trapped& trap) noexcept -> ca::verdict {
		if (!trap.resumable())
			return ca::verdict::pass;
		if (this->from->spare == 0)
			return ca::verdict::pass;
		--this->from->spare;
		++this->from->free;
		return ca::verdict::resume;
	}

	auto enter(pool& p, const int count) noexcept -> void {
		this->from = &p;
		for (int i = 0; i < count; ++i)
			take(p).raise();
	}

	auto leave(const ca::error*, const ca::outcome outcome) noexcept -> void {
		this->ended = outcome;
	}
};

auto main(void) -> int {
	pool p{1, 1};
	refill r{};
	if (!r.run(p, 2) || p.spare != 0 || r.ended != ca::outcome::succeeded)
		return 1;

	auto outer = ca::with(
		[&](void) noexcept {
			static_cast<void>(r.run(p, 1));
		},
		[](const ca::error*) noexcept {});
	if (outer || outer.error() != ca::errc::out_of_memory || r.ended != ca::outcome::passed)
		return 2;

	auto only_mine = ca::with(
		ca::handler{[](const ca::trapped& trap) noexcept {
			return trap.reason() == ca::sv::str{"mine"} ? ca::verdict::take : ca::verdict::pass;
		}},
		[](void) noexcept { ca::trap("mine"); },
		[](const ca::error*) noexcept {});
	return only_mine ? 3 : 0;
}
```

In the second run the pool is empty and `refill` has no spare: it passes the `ask`, `take` returns its failure, `raise` traps, `refill` passes that trap too, and the outer context takes it, after `refill`'s `leave` saw `passed`.

## `context_manager.hpp`

### class `context_manager`

```c++
template <typename Self, typename E = ca::error>
class context_manager;
```

CRTP base of a context, Python's with statement without exceptions. Self holds the state and provides `enter(args...) -> void` (or `-> result<void, E>`) and `leave(const E* error) noexcept -> void`, or `leave(const E* error, ca::outcome)` to know how the context ended. self.run(args...) calls enter inside a new context, then leave: error is nullptr on success, else what the context fails with, which run returns. ca::ctx\<Self>::run(args...) does the same on a new Self.

Every ca::trap reached inside enter goes to the contexts, innermost first. Self may provide `handles(const ca::trapped&) noexcept -> ca::verdict`, called at the trap site before anything unwinds: take the trap, pass it to an outer context, or resume a ca::ask. Without handles, a context takes every trap and passes every ca::ask. A context passed over still runs leave, with outcome passed, during the trap; its run never returns. handles, and leave when passed, must not trap: that stops the program.

Accessing a failed result (`*r`, `r->`, `r.value()`, `r.raise()`) fails the context taking it with r's error: as it is when of type E (moved out of r when E cannot be copied), else its ca::error (an error() of it) made an E, its trace extended with the reason. Any other trap fails it with errc::not_recoverable and the reason. E is ca::error or made from one (ca::report\<A>, by E::of). Frames skipped this way are never unwound, so their objects must be trivially destructible (every ca owner is); what they acquired belongs in Self, for leave to release. Contexts nest, per thread.

## `impl/`

`run_context.hpp`: the one function every context goes through, for `ca::with`, `ca::context_manager` and `ca::ctx` alike.

`run_context<E>(handles, enter, leave)` pushes a recovery point (layer 1, `impl::recovery`), runs `enter`, pops the point and calls `leave(error, outcome)` with nullptr on success or the error otherwise. The error is what `enter` returned when it returned a failed `result<void, E>`, or what a trap it took left on the point: the failed result's own error when the trap came from reading one (an E taken whole, moved when it cannot be copied, else its `ca::error` made an E), or `errc::not_recoverable` with the trap's reason in a new trace frame (`traced_error`).

`handles` is `takes_every_trap` for a context without one: the point then has no `_handles`, and the trap machinery takes every trap and passes every `ca::ask` for it. Otherwise the point carries `decide_context` (handles on a `ca::trapped`) and `unwind_context`, which runs `leave` with outcome `passed` while a trap goes past: with the trap's E as it is, else its `ca::error` made an E and cleaned up after. `traced_error` records the reason in the trace once, on the trap, so every context the trap meets sees the same error. `leave_state` calls `Self::leave` with the outcome when it takes one.

`is_context_error<E>` admits the error types a context may fail with: `ca::error`, or a type made from one through `E::of(error)` (as `ca::report` is) or a constructor.

`enter_recovery` is the function that calls `__builtin_setjmp`. It is `gnu::noipa` on gcc: when the body never returns normally, gcc's interprocedural analysis would otherwise conclude that the landing path is the only exit and drop the body's stores before a trap, which the caller then would not see. Clang only needs it out of line.

## `memory/`

Allocators: where every allocating type of ca gets its memory. Each container, string and owner is templated on its allocator (`A = ca::heap`), so the same code runs on the general heap, in an arena, or on fresh pages.

| Allocator | Kind | Use |
|---|---|---|
| `ca::heap` | stateless | the default: per-thread size classes, no lock on a thread's own blocks |
| `ca::page_allocator` | stateless | whole pages per block, zeroed, grown by remapping without copying |
| `ca::libc_allocator` | stateless | malloc, realloc and free: the baseline benchmarks compare with |
| `ca::arena_allocator` | stateful | blocks of a `ca::arena`, released all at once |

### The allocator contract

An allocator (`ca::is_allocator`) is a cheap value, copied without failing, with two members:

- `allocate(size, alignment) const -> result<allocation>`: a block of at least size bytes; the `allocation` returned carries the address and the usable size, which may be larger.
- `deallocate(block, alignment) const -> void`: hands a block back; never fails.

Optionally `expand` (resize in place), `reallocate` (resize, moving if needed) and `allocate_zeroed`. The free functions `ca::expand`, `ca::reallocate` and `ca::allocate_zeroed` use them when present and fall back to allocate, copy and deallocate otherwise, so a minimal allocator works everywhere. The `_n` forms (`allocate_n<T>`, `reallocate_n<T>`, `expand_n<T>`, `deallocate_n<T>`) count in objects and check the multiplication for overflow.

An allocator that declares `static constexpr bool STATELESS = true` is stateless: every instance is interchangeable, and allocator-aware types store it in no space. Others are stateful: memory goes back through the allocator it came from, and the types holding one have no default constructor.

```c++
#include "ca/integers.hpp"
#include "ca/memory.hpp"
#include "ca/optional.hpp"

auto main(void) -> int {
	const ca::heap heap{};
	auto block = ca::allocate_n<int>(heap, 10U);
	if (!block || block->size() < 10U * sizeof(int))
		return 1;
	int* const values = static_cast<int*>(block->data());
	for (int i = 0; i < 10; ++i)
		values[i] = i;

	auto grown = ca::reallocate_n<int>(heap, *block, 1000U);
	if (!grown || static_cast<int*>(grown->data())[9] != 9)
		return 2;
	ca::deallocate_n<int>(heap, *grown);

	auto zeroed = ca::allocate_zeroed(ca::page_allocator{}, 10000U, 64U);
	if (!zeroed || zeroed->size() < 10000U || static_cast<ca::byte*>(zeroed->data())[9999] != 0U)
		return 3;
	ca::page_allocator{}.deallocate(*zeroed, 64U);
	return 0;
}
```

### Arenas

`ca::arena` owns chunks of pages and hands out blocks by bumping a pointer: allocation is a few instructions, and `cleanup()` releases everything at once, or `reset()` empties it for reuse. It is an allocator resource (`ca::is_allocator_resource`): not an allocator itself, it gives out `arena_allocator`s, one pointer wide, which must not outlive it. Deallocating only gives memory back when the block is the newest one. Arenas are not thread-safe.

```c++
#include "ca/dynamic_array.hpp"
#include "ca/make_in.hpp"
#include "ca/memory.hpp"

auto main(void) -> int {
	auto made = ca::arena::make();
	if (!made)
		return 1;
	ca::arena& arena = *made;

	ca::dynamic_array<int, ca::arena_allocator> squares{arena.allocator()};
	for (int i = 0; i < 1000; ++i)
		if (!squares.append(i * i))
			return 2;

	auto other = ca::make_in<ca::dynamic_array<int>>(arena);
	if (!other || !other->append(42))
		return 3;

	const bool ok = squares[999] == 999 * 999 && (*other)[0] == 42;
	if (!squares.cleanup() || !other->cleanup())
		return 4;
	arena.reset();
	return ok && arena.cleanup() ? 0 : 5;
}
```

`ca::allocator_of<R>`, `ca::as_allocator(source)` and `ca::is_allocator_source` unify the two kinds of source, so `make_in` takes either an allocator or a resource.

### The heap

`ca::heap` serves sizes up to 128 KiB from 48 size classes (16 to 128 bytes by 16, then four per doubling, so at most 25% above the size asked for), each thread from its own 1 MiB spans with no lock and no atomic. A block finds its span by masking its address, so there is no per-block header. Any thread may free any block; one freed away from its owner goes back with a single atomic operation. Larger sizes are mapped pages, and growing them remaps without copying. The performance notes of `heap.hpp` give the costs per operation.

`ca::heap` is one instantiation of `ca::basic_heap<Pages, G, Binding>`, the same engine with its three dependencies as parameters, for code where mmap and threads are not the right ones (a kernel: frames for pages, one heap per CPU, interrupts off while a heap is touched):

| Parameter | ca::heap | Role |
|---|---|---|
| `Pages` | `ca::page_allocator` | stateless allocator of spans (aligned to their size), large blocks, heap states |
| `G` | `ca::heap_geometry` | `ca::is_heap_geometry`: span size, largest class, spare spans, state chunk, `STATISTICS`, `CHECK_DOUBLE_FREE` |
| `Binding` | `ca::heap_thread_binding` | where the current heap is (`current`), what keeps others off it (`pin`, `unpin`), how a new one is installed (`adopt`) |

The fast paths are in `basic_heap.hpp`; the rest is in `impl/heap_engine.hpp`, which only the translation unit instantiating the heap includes. With `STATISTICS`, `statistics()` sums every heap's counters: blocks in use and spans per class, spare spans, large blocks and their bytes. With `CHECK_DOUBLE_FREE`, a bit per 16 bytes of each span marks the blocks in use, and a block freed twice, or an address off a 16-byte boundary, traps, in every build.

```c++
#include "ca/memory.hpp"
#include "4-lifecycle/memory/impl/heap_engine.hpp"

struct small_spans final {
	static constexpr ca::usz SPAN_SIZE = 65536U;
	static constexpr ca::usz LARGEST_CLASS = 2048U;
	static constexpr ca::u32 SPARE_SPANS = 0U;
	static constexpr ca::usz STATE_CHUNK = 4096U;
	static constexpr bool STATISTICS = true;
	static constexpr bool CHECK_DOUBLE_FREE = true;
};

template <typename Heap>
struct one_heap final {
	using state = typename Heap::state_type;
	static constinit inline state* _current = Heap::empty_state();
	struct token final {
	};
	static auto current(void) noexcept -> state* { return _current; }
	static auto pin(void) noexcept -> token { return token{}; }
	static auto unpin(token) noexcept -> void {}
	static auto adopt(state* const heap) noexcept -> void { _current = heap; }
};

using my_heap = ca::basic_heap<ca::page_allocator, small_spans, one_heap>;
template class ca::basic_heap<ca::page_allocator, small_spans, one_heap>;

auto main(void) -> int {
	const my_heap heap{};
	auto block = heap.allocate(100U, 8U);
	if (!block || block->size() != 112U)
		return 1;
	const auto held = my_heap::statistics();
	if (held.small_blocks() != 1U || held.small_bytes() != 112U)
		return 2;
	heap.deallocate(*block, 8U);
	return my_heap::statistics().small_blocks() == 0U ? 0 : 3;
}
```

## `memory/basic_heap.hpp`

The heap engine behind ca::heap, for heaps that get their pages, their notion of "current" and their size classes from elsewhere (a kernel: frames, one heap per CPU, interrupts off).

ca::basic_heap<Pages, G, Binding>:

- Pages, a stateless allocator: spans (G::SPAN_SIZE bytes aligned to G::SPAN_SIZE), blocks past G::LARGEST_CLASS, and chunks of heap states. Its expand, reallocate and allocate_zeroed are used when it has them. With G::STATISTICS, a static or const usable_size(size, alignment) gives the bytes a large block of that size holds, the same for the size asked and the size returned; without one, sizes round up to Pages::ALIGNMENT.
- G, a geometry (ca::is_heap_geometry).
- Binding, a class template instantiated on the heap (Binding<basic_heap<...>>), with static members: current() returning the calling context's state_type* (the heap's empty_state() until adopt), always inlined; pin() and unpin(token), around every use of a heap's own spans, so that nothing else runs on that heap meanwhile (nothing for a thread's heap; interrupts off for a CPU's); adopt(state_type*), called once a context got its heap, outside any lock of the heap, which makes it current. A context whose heap goes away for good (a thread exiting) passes it to retire(), after pointing current() back to empty_state().

The class holds the fast paths; the rest is in impl/heap_engine.hpp, which only the translation unit instantiating a heap includes, then names it: `template class ca::basic_heap<...>;` (heap.cpp does it for ca::heap). Two instantiations share nothing.

## `memory/heap.hpp`

Performance of ca::heap.

Layout: per thread, a heap of 48 size-class queues of 1 MiB spans aligned to their size; each span serves one class from its start, its 128-byte header in the last bytes. A block finds its span by masking its address: no per-block header, and deallocate needs the size only to tell small from large (past 128 KiB, page_allocator).

| Operation | Time | Notes |
|---|---|---|
| allocate, small, block on the free list | O(1) | ~10 instructions inline: TLS load, class from size (shift, or bit_width for >128), pop |
| deallocate, small, same thread | O(1) | ~15 instructions inline: mask, owner compare, push |
| allocate, list empty | O(1) amortized | out of line: take remote frees, else carve a page of fresh blocks, else next span or a new one |
| deallocate, other thread | O(1) | one CAS on the span's list, or on its heap's when the span is full |
| allocate, deallocate, large | one syscall | mmap / munmap |
| reallocate | O(1) within a class or large to large | large to large is mremap: no byte copied |

Space: classes 16 to 128 by 16, then four per doubling, at most 25% over the size asked for; blocks are carved a page at a time, so untouched spans cost address space only. An emptied span goes back to the system unless it is its class's first; two per heap are kept for reuse.

Threads: no lock and no atomic on a thread's own blocks. A block freed by another thread goes to its span's atomic list, collected when the owner runs out; a span marked full sends such frees to its heap instead, so that the freeing thread never touches a span the owner may release. Heaps are never freed: an exiting thread's heap (thread key, exit stage memory) goes to a pool under a spin lock, the next new thread adopts it with its spans. A fork while another thread holds that lock leaves the child unable to start a new heap.

Measurements: see dynamic_array and path; against glibc malloc, 1.25x to 2.5x faster on allocation-heavy cases, equal elsewhere.

The general-purpose, stateless allocator, default of allocator-aware types. ## `memory/impl/`

The internals of `ca::heap` and `ca::arena`.

### Heap

Everything below is templated on the geometry `G` (`ca::is_heap_geometry`) of a `ca::basic_heap`; `ca::heap`'s is 1 MiB spans and classes up to 128 KiB.

- `heap_classes.hpp`: up to 48 size classes, 16 to 128 bytes by 16, then four per doubling up to `G::LARGEST_CLASS`. Every class is a multiple of 16. `heap_class_of(size)` is a shift for small sizes and a `bit_width` above 128, always inlined: it sits on the allocation fast path.
- `heap_span.hpp`: a span is `G::SPAN_SIZE` bytes aligned to its size, serving one class from its start, its header in the last bytes, so `heap_span_of(block)` finds it by masking the block's address. The header's first cache line belongs to the owning heap (its free list, its use count); the second takes frees from other heaps, as an atomic list, or the full mark once the owner found the span exhausted, after which such frees go to the owner heap's `_pending` list instead, so a foreign thread never touches a span the owner may release. With `G::CHECK_DOUBLE_FREE`, a bit per 16 bytes, right below the header, marks the blocks in use (`heap_mark`, `heap_unmark`, which also traps on an address off a 16-byte boundary); frees from other heaps are checked when the owner collects them.
- `heap_state.hpp`: a heap, holding per class a queue of spans with room, and with `G::STATISTICS` its counters (blocks in use and spans per class, spare spans), written by the owner alone with relaxed stores. Contexts that have not allocated yet point at the heap's `empty_state()`, whose classes all hold the empty span, so the fast path has no null check: the first allocation takes the slow path, which builds a real heap and gives it to the binding. Heaps are never freed: a retired one (`ca::heap`: a thread's exit, through a thread key) goes to a pool, and the next new context adopts it with its spans.
- `heap_engine.hpp`: the slow paths, the pool and the large-block counters of one instantiation, internal to the translation unit that includes it and names the instantiation.
- `heap_traps.hpp`: the named traps of the heap's checks.

### Arena

`arena_state.hpp`: an arena's state lives in its first chunk, right after the `arena_chunk` header (previous chunk, size), so it never moves and the `arena_allocator`s, which point to it, stay valid when the `ca::arena` object itself is moved. Blocks are carved from `_top` up to `_end` of the newest chunk; a request that does not fit starts a new chunk, or gets a chunk of its own when larger than the chunk size.
